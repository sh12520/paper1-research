# Soundness review of lazy depth-3 grammar search

This review applies to the frozen six-cell interpreter and the original profile and operator domains. Depth 3 changes only the maximum composition depth for this feasibility study. At depths 1–2 the original FLAT structural domain allows one or two mechanism groups. At depth 3 the extension allows all one through four structural groups; the original two-group experimental restriction is not carried over. B2 remains its own static route. A depth-3 signature order does not imply an ordinal from an external depth-3 graph.

## Why an eager depth-2 compiler is not an appropriate extension

With one parameter value per operator, the fully available domain has two binary and three unary constructors. Let `F_d(x)` count allowed shapes by number of `Static` positions. Then `F_0(x)=x` and `F_d(x)=x+3F_(d−1)(x)+2F_(d−1)(x)^2`. Evaluating at `x=1` gives 91 shapes at depth≤2 and 16,836 at depth≤3. Weighting the coefficient of `x^k` by Bell number `B_k` counts shape-and-profile-equality cases: 369 at depth≤2 and **2,445,064** at depth≤3 before relevance reduction, duplicate removal, or scoring. The largest shape has eight leaves and admits 4,140 equality partitions. These are arithmetic counts of symbolic construction cases, not estimates of complete semantic classes. The previously tested depth-2 quotient remains valid per operator shape, but eagerly compiling every depth-3 shape and partition would be a separate, costly upfront computation.

The depth-3 design instead extends the operator skeleton best-first from typed clause holes. The public envelope bounds every concrete completion of a partial skeleton. Profile equality partitions are considered only for skeletons this frontier actually opens. An unresolved skeleton covers all its pending partitions and stays represented in the certificate until its partition processing finishes. Keeping only an arbitrary prefix of skeletons or partitions would not establish exactness.

## Which profile positions can be ignored

Number every `Static` occurrence by position in a complete operator skeleton. Resolve raw schedule transport over the root's six time/state cells using the frozen rules for `If`, `Sequence`, `Delay`, `ValidFor`, and `Offload`. Also resolve each raw `If`'s left and right child as standalone contracts over the same six cells. The relevant occurrences are the union of profiles reached by all these observations. The second set of observations is necessary even if the root never executes the affected child cell.

For every fixed assignment of profiles, raw and normalized dispatch have the same active/idle status, profile and offload level at an observed cell. The claim follows by induction. Ordinary wrappers preserve the dispatch after transporting time/state. If a conditional stays, raw and normalized dispatch choose the same child. If it collapses, both child keys are identical. At the selected cell both normalized children thus have the same idle/profile/level, so choosing either normalized branch preserves this projection. A collapsing branch can select a different lexical representative; it still has the same child signature.

Now change a profile outside all relevant positions. An innermost `If` still compares two identical-to-before child keys. Its child observations see no change of profile/idle/level. Fixed typed operators, producer capabilities, whole footprint scopes and the membership-based profile predicates are unaffected. Inducting upward over conditionals leaves all collapse decisions unchanged. At the root the declared footprint, six cell roles, levels, activity and public profile IDs are therefore unchanged. This covers operators in an inactive branch: the branch's fixed footprint is retained, although a profile position inside it may be irrelevant.

The distinction is observable in `If(moving, If(moving, Static(a), Static(b)), Static(a))`. The root never reaches `Static(b)`. Setting `b=a` removes both conditionals; a different `b` can preserve them even though every active cell has the same visible profile `a`. Including each `If` child key observation keeps this position relevant. By contrast, a profile position outside every observation needs no all-different constraint. It can independently use the lexically least static serialization, even if that profile also occurs elsewhere.

## Transfer, quotient, and witness

Within the relevant positions, an equality partition fixes every profile equality test. Renaming its distinct groups injectively preserves every normalized child signature comparison. The packed result changes only in its occupied profile bytes. This is the same argument used for depth 2 in `GRAMMAR_DEDUP_SOUNDNESS.md`. The depth-3 transfer still uses the same six-cell shifts, scopes, and positive public predicates. Repeated wrappers add a role to a set; they do not add another invocation. The role-mask cost and the base-demand rule therefore need no new depth-3 definitions. Preconditions or operator semantics outside the frozen positive-predicate public basis must fail closed instead of inheriting this proof.

The complete template key consists of the full packed flags and footprint prefix, all six cells' idle or visible-group markers, level and role bytes, and the visible-group pattern canonicalized in cell order. Two different templates cannot instantiate the same concrete key. Identical templates can share a single visible assignment stream while keeping the union of their raw witness recipes. Every valid assignment of distinct public profiles to visible groups has an extension to its hidden relevant groups if the partition does not use more groups than the domain contains. Unknown occurrences outside relevance can independently take their least raw static key. For hidden *relevant* groups, select the least available profile in order of their first raw occurrence, excluding the visible values and previously assigned hidden groups. All groups use the same public domain, so this rule retains an all-different extension and minimizes raw text. Compare the actual instantiated raw keys of all recipes, then normalize the winning AST against the original public interpreter. Choosing the best dummy recipe alone would fail to account for lexical order under actual assignments.

## Lower bound and exact certificate

Both the unresolved-skeleton bounds and the pending visible-assignment bounds use the existing frozen FLAT public score. For a template, the latter bound fixes levels and cell roles and relaxes remaining profile domains independently at each cell. The real completion's profile remains in each relaxed domain, including when multiple cells share one variable. This relaxes equality correlations without removing a candidate. The existing monotone coordinatewise argument and the downward rounding allowance for the additional joint cell bound in `GRAMMAR_BOUND_SPEC.md` apply on the same physical public domain and score expression, regardless of depth. Group counting uses the mandatory normalized footprint or the exact template prefix. Capability, predicate, and depth rules are checked during shape construction; pruning an infeasible-looking individual schedule is unnecessary for the FLAT order.

The next candidate is certifiable when its exact score is strictly below the lower bound of **every** unresolved skeleton and profile-assignment state, allowing also an empty frontier. Exact score followed by lexicographic packed key orders the complete queue. The strict test exhausts every possibility for an equal-score earlier key or a later-discovered lexical recipe of the same key. This preserves depth≤2 class ID tie order, since those IDs are positions of sorted packed keys. At depth 3 it defines a consistent extension by packed byte order. A resource limit leaves a certified prefix already emitted under that rule; a pending or merely scored candidate beyond that prefix is not certified. Neither the proof nor a limited run establishes depth-3 full-domain runtime.

## Scope of the guarantees

| Obligation | Depth-independent argument under the fixed interpreter | What the depth-three study checks |
| --- | --- | --- |
| Context congruence and normalization | Constructor composition and equality-based IF normalization give structural induction over any finite tree under the frozen six-cell and role semantics. | The deeper implementation adds lazy skeleton compilation and validates its normalized witnesses and signature order. |
| Invalid and unavailable subtrees | The frozen typed productions bind their own role and parameter domains. The prior irreparability argument for recursive V3 validity applies within its documented scope. Arbitrary unsupported scopes, predicates, and registries require separate analysis. | The worker expands only allowed productions and checks the frozen positive predicate basis. Reduced controls test missing roles and rejection at intake. Public physical infeasibility is left to the verifier. |
| Envelope and score bound | The abstract operator transfers and arithmetic score inequality are independent of AST depth while the fixed six executable cells, profile domain and score expression apply. | The reduced oracle checks original envelope bounds as well as the bounds actually used by the new shape and assignment queues. |
| Semantic quotient and representative | Equality partitions and observation relevance yield a quotient by structural induction as long as each pending symbolic derivation remains represented. | The older eager quotient was validated only through depth 2. The new depth-three lane must preserve hidden positions used by normalization tests, partition coverage and the final lexical representative. |
| Termination certificate | A finite covered frontier plus strict score separation is sufficient at any finite depth. | The worker implements this through depth 3, including pending partition expansions and stable ties. Resource feasibility is measured on the fixed 24 queries. |

## Independent reduced-domain test

`results/depth3/check_reduced_depth3.py` constructs reduced **in-memory testing domains** from one existing serialized public record. It retains one or two existing profiles and deliberate operator subsets. An independent raw AST enumeration invokes `CompactEncoder.encode` and the original NumPy `_proxy` and lexicographic sorting operations. The test compares complete key sets, bitwise scores, order, and both raw and normalized witnesses, followed by complete exhaustion. It checks every grammar-envelope hole expansion against its true descendant minimum. A test-only subclass also checks the operative skeleton and profile-assignment frontier bounds against exact descendant minima grouped independently by shape prefix and symbolic assignment context.

The final test passed all ten reduced (operator scope, depth) cases. It compared 18,896 complete syntax leaves and 670 eligible structural signatures. Checked lower bounds included 40,878 abstract partial contracts, 21,254 live skeleton states, and 682 live assignment states. The four-group positive control contains 248 group-4 classes at depth 3. The unavailable-offload control has no structural class. An unsupported public predicate failed closed at cursor intake. Results with the exact `depth_search.py` digest are in `results/depth3/reduced_depth3_correctness.json`. These oracle checks establish behavior in deliberately reduced domains. Full-domain certification and engineering bounds are measured separately.
