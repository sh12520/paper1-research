# PILOT identity grid and inherited diagnostic subsets

`PILOT01_PLAN_TEMPLATE.json` contains only the 1,920 identity slots for the
96 existing configurations and indices 0 through 19. It does not contain
derived seeds, public instances or private preferences; it does not authorize
PILOT execution. Depth remains 1 or 2 as in the current config.

For the existing common engineering integrity aggregation, the following
public coordinates are inherited exactly from the SMOKE-02 engineering
diagnostics: four candidate audits use each family at medium pressure, high
conflict, rich capabilities, depth 2 and index 0; eight repeats use those
same coordinates with indices 0 and 1; sixteen fresh repeats use each family,
pressure low or high, medium conflict, sparse capabilities, depth 1 or 2,
and index 0. The pilot identity plan itself remains 1,920 paired slots.

These selections are reproducibility and implementation diagnostics only.
The earlier research preregistration did not explicitly designate these
subsets as preregistered PILOT-specific checks; this document does not claim
that it did, and it does not add or alter research Gates A–E. The existing
preregistration also describes four canonical unit cases separately from the
1,920 random pilot instances; their execution and reporting must remain
visible in the later authorized PILOT plan.
