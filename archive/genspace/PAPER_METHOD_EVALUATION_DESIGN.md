# Paper method evaluation design

The evaluation has four questions. Does the cursor preserve the frozen public ranking and representative at depth≤2? Which components reduce search work or elapsed time on a fixed eligible domain? How does a certified candidate stream behave under the existing bilateral protocol? What depth-three coverage can it certify under a fixed resource budget without a complete graph? The experiments described here are prospective. The existing gate reports supply development evidence, and the companion preregistration draft supplies proposed held-out identities, caps and decision thresholds.

## Comparison scope

Pair all applicable methods on the same serialized input, allowed depth, grammar parameters, public profile domain, capability registry, score, tie rule, verifier and budget. Preserve the original public conditioning at depth≤2, including the one-or-two mechanism-group eligibility rule. The existing depth-three extension allows one through four groups. All methods at that depth must share this extended domain. The development contrast between depths two and three includes the domain change. A pure depth comparison would require a separately preregistered matched group cap.

Use the lexicographic key `(binary64 public score, unsigned compact semantic signature)`. In the archived FLAT graph, ordinal class IDs implement that signature order. For any safe pruning step, require a proof that all excluded derivations are either ineligible or cannot alter the requested order and representative. A partial envelope may guide or bound public search. The ranked domain includes candidates that can fail the downstream physical verifier. Public verification and bilateral acceptance stay downstream. The generation and ranking interface receives public input only.

## Required comparison lanes

| Lane | Implementation scope | Role in the comparison |
|---|---|---|
| **Full FLAT scan** | Archived exact depth≤2 graph, original availability/depth/group conditioning, full original `_proxy` scoring and sort. Retain the optimized vectorized implementation and exact tie order. | Gold reference for ranked signatures and score bits in the frozen depth≤2 domain. Also supplies work and timing for scanning the entire conditioned universe. **Depth-three full FLAT is N/A**. No full depth-three graph, ranking or runtime is available. |
| **Generic multidimensional index** | Archived single-tree public-feature index. It shares public score inputs, admissible ranking, leaf budget accounting and exact filter rules with the contract-aware lane. Include warm retrieval and separate offline construction/storage. | Strong graph-based comparator for general spatial partitioning. Available over the frozen depth≤2 graph. Depth-three index results are N/A. |
| **Contract-aware index** | Archived exact best-first forest with the same public features and final ranking, partitioned using capability/depth availability and structural footprint. Include index construction and graph prerequisites. | Strongest archived structure-aware graph-based comparator. Available over depth≤2 only. A depth≤2 restricted search on a depth-three query can be reported as a separate restricted-domain comparator if preregistered, with its original domain explicitly named. |
| **Generic partial-program best-first search** | Begin from typed holes over the same query domain, use conventional admissible interval bounds for the frozen score, deterministic hole filling and exact leaf scoring. Use memoization for identical search states, terminal semantic deduplication, and the same cutoff and canonical witness proof. Match implementation effort and numerical accounting. | Controls for graph-free generic best-first search. Run the predeclared ordinary and strengthened variants below at each applicable depth. |
| **Current domain-specific grammar search** | Run the current public grammar cursor with its contextual quotient, state/time/resource envelopes, capability-aware generation, exact lexical recovery and lazy certificate. Freeze the applicable method version for each depth and record that version and admissible domain. | Evaluates the combination of the current components. The graph and archived outcomes remain outside the online method. |
| **Major ablations** | Run the six matched switches below around the current method. Each arm retains eligible semantics, scores, ties, representative rules, verifier and protocol. | Separates component effects on certification, search work, memory, timing and negotiated outcomes. |

Alongside an ordinary fixed-hole generic branch-and-bound order, preregister a stronger exact generic variant using a deterministic most-constrained-hole rule, domain splitting and generic admissible interval propagation over public score inputs. Choose ordering ties by a fixed public rule. Generic search may cache typed states and reuse the same public score kernel. It must maintain a global valid lower-bound frontier even if a secondary exploration heuristic prioritizes finding incumbents. This control tests common search engineering without requiring a contextual semantic quotient. Both variants must pass reduced-domain exhaustive checks and reproduce original depth≤2 FLAT order where certified. Use the variant selected on development data as the prespecified primary generic comparator and retain both measurements. Explore in any admissible order while preserving all equal-score witnesses and a bound-based proof of each exclusion.

The two index baselines already have documented implementations and bounds. The earlier grammar gate supplies development evidence on duplication, including capped cases under a different implementation. The proposed generic synthesis comparison runs on the matched legal domain and protocol. ## Six one-factor ablations

Correctness is required for every certified output. The effects on work, runtime and memory below are hypotheses. Each switching boundary must be audited against the same eligible signatures and normalized witnesses on reduced exact domains before interpreting performance. Record the resources freed by each switch and the work that replaces them.

| Ablation | Switch and fixed semantics | Correctness hypothesis | Work hypothesis | Time and memory hypothesis |
|---|---|---|---|---|
| **A1. No semantic deduplication in search** | Disable early merging of contextually equivalent partial/symbolic states and transfer individual derivations at complete leaves. Retain terminal signature checking, exact emitted uniqueness and the least valid lexical witness for each key. An exact score can be reused after terminal signature equality has been established. Close all competing derivations at a tie before emission. | Same unique ranked keys and canonical witnesses for the certified prefix. Terminal identity bookkeeping is essential to preserve the ranking. | More raw derivations and late duplicate work. Distinct output signatures at a matched certified K remain unchanged. Record repeated score calls if performed. | Expect slower certification where collisions dominate. Less quotient storage can save memory locally, while a wider frontier and more terminal duplicate bookkeeping can increase peak memory. |
| **A2. Generic bound** | Hold the public envelope and its cached states fixed. Replace the domain-specific tightening with a generic outward interval mapping of each score term over the envelope's independent public ranges. Apply the sign of each term and conservative binary64 rounding. Keep the same exact score at leaves. | Every pruning/stop certificate remains admissible and preserves ties. A proof is required for the substitute bound. | A looser lower bound can force more pending states and complete candidates to be examined before a certificate. | Simpler bounds can lower cost per expansion. Extra expansions and pending states may increase online time and memory. |
| **A3. No capability-aware early pruning** | Move the same availability test from early production rejection to a late derivation check. Apply it to the raw typed derivation before enabling normalization or lexical witness eligibility. This prevents unavailable syntax that later collapses from influencing the representative. Keep profile and depth legality unchanged. | Same availability-conditioned classes and admissible witnesses. Invalid derivations never enter scoring, candidate output or protocol. | Extra partial states and rejected derivations, particularly on sparse public capabilities. | Expect a larger cost on sparse queries. Early public-role checks can have a small per-state cost, so time and memory direction require measurement. |
| **A4. No enhanced state/time/resource envelope** | Keep the method's bound function. Feed it a minimal sound public envelope obtained by widening operator-specific dispatch and role/context information to conservative per-cell options and resource extrema. Keep public typing, capabilities, normalized identity and quotient eligibility intact. | Same certified results if widening contains every completion, including possible conditional collapses and crop effects. | Weaker envelopes can cause more proof work and candidate scoring. Fewer distinct envelope computations or cache entries are possible. | Simpler envelope construction can save CPU and cache memory. A wider frontier and delayed certificates can dominate either effect. |
| **A5. No lazy stopping** | Keep the search, ranking and exact proofs. Once structural retrieval is required, continue through the finite domain before releasing a requested structural prefix. Keep the original B2 stage and ordinary terminal agreement rule. A bounded prefix buffer is permitted; building a new full depth-three graph is outside this arm. | Full exhaustion yields the same prefix and original protocol trajectory for the same candidate stream. An interrupted exhaustive lane has incomplete delivery even when a shorter prefix certificate had already become possible. | Additional states and candidates are processed beyond the first valid cutoff. Record time to proof and time to delivery separately if both exist. | Expect larger time to deliver small prefixes and early agreements. Peak memory depends on frontier and retained state/candidate buffers, which must be reported. Keep the same per-query caps. |
| **A6. No domain-specific normalization during search** | Suppress early operator-aware state normalization and canonicalization. Retain the frozen complete-contract normalizer, one-key semantics, canonical witness policy and existing validator. Allow sound generic memoization on unchanged raw state identities. Preserve both legal branches of unresolved equivalences in the public envelope. | Same semantic domain, score and tie order at complete output. A no-op replacement for final normalization would change semantics and is excluded. | Less opportunity to align and merge equivalent intermediate states; more terminal normalization and proof work where redundant syntax is common. | Early normalizer overhead falls, while terminal work and pending state growth may increase. Report memory and wall time separately. |

If a switch cannot be isolated without changing another component's legality or proof obligations, record that dependency before experiments. In particular, early normalization can expose quotient merges. Preserve semantic equivalence and explain the dependency; a bundled comparison should be identified as such rather than interpreted as the isolated effect of normalization. Keep role, capacity and acceptance rules fixed throughout.

## Metrics and accounting

| Question | Primary records | Interpretation |
|---|---|---|
| **Exact ranking and certification** | Record exact ordered keys, score bits, canonical witnesses, requested/returned K, full-length flag, proved exhaustion flag, cutoff score and best remaining bound/key. Compare Top-K with original FLAT at depth≤2. For depth three, audit reduced-domain exhaustive cases and the full frontier certificate for emitted prefixes. Report certified completion, full-length coverage, valid domain-short coverage, work/time caps and unsound evidence separately. | A certified result at K requires K valid unique candidates or proof of complete exhaustion of a smaller domain. Every reported prefix must honor the same total rank. Depth-three has no observed exhaustive global FLAT Top-K reference. |
| **Search work** | Record complete syntax materializations, canonical witness constructions, instantiated complete signatures, distinct complete semantic states, raw leaf duplicates, exact score calls, partial states generated/expanded, shape and assignment work, symbolic partition probes, merged states and frontier peak. For graph lanes, count candidate metadata touches and index-node visits separately. | Counts must name their units. A partition probe, tree-node visit, complete AST, distinct semantic class, evaluated score and exact verifier call are different events. A method-specific partial-state quotient count cannot stand in for a shared complete-class count. |
| **Runtime and memory** | Record online public search median/p95 and peak work set, with query setup, on-demand template construction, ranking/bounds and certificate accounting included. Also record protocol-inclusive elapsed time and memory. Report graph/index generation, persistent sizes, auxiliary availability artifacts, loading/warming and per-query storage as separate prerequisites. | Use paired query IDs and the same resource policy. Mark measurement clocks precisely. Distinguish time to certificate, time to delivery and end-to-end agreement time. Report completion coverage alongside conditional timing percentiles. Elapsed time at a cap is an observed attempt and, where applicable, a lower bound on time to completion. |
| **Negotiated outcomes** | Start with original B2, use unchanged verified batches, maintain proposal history and compare at the original budget checkpoints. Record verified agreement, normalized representative, both utilities, Nash welfare, exact verification calls, proposal rounds and proved exhaustion/unknown status. | For a run yielding no verified agreement, a time, search or verification cap leaves existence unknown unless the evaluated domain and acceptance check were exhausted. Exact Top-K alone says nothing about acceptance. Count every attempted query in the agreement/status panel. Compare Nash only for paired verified agreements with a declared reference and report that denominator. |
| **Scaling and coverage** | Stratify by depth, family, public capacity pressure, richness, legal complete-domain size where known, and K. Record per-cell certification and elapsed/work/memory sensitivity. Compare the original complete depth≤2 graph size and index costs with method-specific online work. | Compare like domains within depth. Report depth-three coverage and resource limits under the declared extension, without imputing a complete depth-three class count or rank. Changes in group scope, capabilities or exhaustion patterns are reported explicitly. |

**Negotiation accounting.** Keep the 27 B2 verification calls, batch boundaries and the original internal B=1000 checkpoint in the budget path even when the report emphasizes B=100, 500 and 5000. Count a proposal when the archived protocol emits a `PROPOSE` event. For each co-verified query, define the signed Nash gap as reference `uA×uN` minus candidate `uA×uN`. Keep gaps for unmatched or unresolved agreements unavailable. A best verified depth-three reward over examined candidates is conditional on those candidates. Only a certified exhaustive proof could support a depth-three optimum or nonexistence claim. Historical O1 and acceptance labels may be read by the independent evaluator after online sealing.

Label the Nash reference in every table. For a matched-budget protocol reference report a signed gap. Report an optimality gap only if the independently verified maximum over the same legal domain is known. A depth≤2 O1 maximum evaluated against a depth-three witness is a cross-domain reference, with its signed difference reported separately.

## Existing evidence and remaining comparisons

The development results already show why the paper needs strong references. The [grammar deduplication performance report](GRAMMAR_DEDUP_PERFORMANCE.md) gives the same 340 high-cost depth≤2 queries for full FLAT (median/p95 1.587/1.931 s), the generic index (0.121/0.860 s), the contract-aware index (0.044/0.484 s) and the graph-free method (0.229/0.435 s). The contract-aware index had the lower median in this cohort. The graph-free method had a lower observed p95 and different offline requirements. These are development observations with archived reference timings.

The current [depth-three feasibility report](results/depth3/DEPTH3_FEASIBILITY_REPORT.md) records exact `(min(K,N))` coverage on all 24 fixed development queries at each requested K. At K=500, 19 had full length and five were proved exhausted with smaller legal domains; the preregistered feasibility rubric returned `DEPTH3_PARTIAL`. The report contains no full graph comparison at depth three. Neither the strengthened generic search nor the six isolated ablations has matched evidence in this review. Execution requires separate authorization and a frozen held-out plan. This design proposes comparisons and measurement boundaries only.
