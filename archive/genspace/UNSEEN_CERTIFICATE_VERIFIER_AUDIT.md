# METHOD-HOLDOUT-READINESS-CLOSE-01 · 独立证书审查

**准备态审查。原深度独立参考通过开发验证。通用 Depth 3 证明供给仍是阻塞项。** 原方法、基线、语法、分数和验证器没有改动。本轮只读取已序列化的开发夹具。 [证书审查实现](results/method_holdout_readiness/unseen_verifier.py)

## 原深度 1–2

裁判在与在线候选生成隔离的离线阶段，以旧快照重新验证已审计 graph 和 availability 的资产来源，逐实例核对公开模型和能力条件。旧快照只作为已有资产凭据。该裁判不打开旧开发前缀，不依赖旧实例身份目录选择查询，也不借用旧授权执行任何研究样本。

每次核对从输入对象的公开部分重建合格域，用原 FLAT 代理式重新评分整个条件化域，按 binary64 分数和无符号规范键排序。直接从冻结可用性资产取 witness 并运行原规范化。全长和短域分别由独立总数和实际排名证明。验证同时比较规范键、分数位模式、见证、长度、声称的穷尽条件及前缀摘要。证书有效性不取决于旧 solver 报出的最小界。

## Depth 3 证据要求

- 所有输出见证逐个重新验证公开参数、构造器类型、深度、能力绑定、scope、predicate 和抽象结构合法性。复算规范键和 FLAT 分数位模式，并检查严格排序、并列键和全局去重。
- 对独立计算定界为至多 10,000 个原始语法树的小域，裁判通过固定的完整语法枚举证明精确前缀或全域穷尽。只在核对范围内保留终端语义键与代表。此流程无 Depth 3 图资产。
- 对不适合小域穷举的查询，`typed-cover-v1` 可表达检查点的覆盖证明。证据绑定公开输入哈希、有效深度、K 和前缀摘要。这棵树从原始根 grammar hole 开始。每个展开由裁判从冻结生成规则独立重建全部、有序、互斥的合法子分支。没有见证且没有独立排除依据的分支不能省略。
- 叶结点由独立语义编码，按相同排名和最小 raw witness 规则归并。空分支需证明无结构机制。对于全长前缀，可用独立计算的区间下界排除后续整棵子树；该下界必须严格大于截止分数，因此同分时仍要展开并验证并列键及 canonical witness。区间界使用冻结抽象转移给出的保守包络，在原 FLAT 的 binary64 运算次序中取 violation/cost 的下界与 margin/quality 的上界。声称穷尽的证据不能使用分数截止省略尚余的合格类。证据消费上限是工程保护，超过时记审查阻塞。

使用两个既有小域分别复核了 81 与 27 个结构语义类，K=10/100/500 六个检查点通过，其中四个为短域。在 81 类查询另外复核了一个 K=10 类型覆盖证据，共 200 帧、130 个通过独立下界排除的子树和 27 个结构空分支。漏掉分支、错误的根下界和换掉公开输入哈希均被判不健全。可归属的资源限额只保持未认证，限额归属由 supervisor 复核。 [独立检查记录](results/method_holdout_readiness/unseen_verifier_evidence.json)

## 仍缺的通用证据

当前冻结游标只输出边界、最小界、缓冲状态和工作计数，缺少能够独立核对未探索区域覆盖完整性的证明。rich 的真实开发查询在 K=10/100/500 的全部三个原生成功声明都因缺少这类证据被裁判置为 `BLOCKED_MISSING_INDEPENDENT_FRONTIER_PROOF`。自报标量上再比对重复记录的标量无法证明整个待处理空间完整。

需要为两个冻结方法输出可复核的源覆盖和安全裁剪证据，或提供经验证的独立覆盖证明生产路径，并在完整 rich 开发域演练证明大小、时间与内存。上述检查展示了如何独立核验合法证据及拒绝缺失证据。它未为一般 rich 查询建立可用的证据生产和复核闭环。Depth 3 的 FULL_FLAT 和图索引仍为 N/A。
