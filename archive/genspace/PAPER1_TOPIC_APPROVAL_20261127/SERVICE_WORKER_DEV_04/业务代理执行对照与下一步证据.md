## 六案原生接口及补救对照

每个实测结果都通过新 HTTP 连接读取了真实后端响应，PNG 摘要和参考一致。两次运行主要行为一致。表中 A 是等待恢复的旧写者，B 是先成功更新的新写者。

| 条件 | 旧请求结果 | 业务入口最终读回 |
|---|---:|---|
| B 改变内容后，A 无条件写 | 200 | A 覆盖 B |
| B 改变内容后，A 带原生旧 ETag | 412 | B 保留 |
| 配置不变，A 超期后使用仍匹配的 ETag | 200 | 路由变为 A |
| B 将内容改走再恢复原值，A 带旧 ETag | 200，ETag 确实恢复为原值 | 路由变为 A |
| 恢复原目标时更新唯一代际标识，A 带旧 ETag | 412 | 恢复后的目标保留 |
| A 发出前由管理侧检查并拒绝已过期任务 | 没有向 Caddy 发送 PATCH | 初始路由保留 |

Caddy 规范中的 ETag 是配置作用域和内容校验值。原生 `If-Match` 的功能是当前作用域的内容并发控制。试验中把不同代际记为同一检查作用域内不重复的 `@id`，恢复相同拨号目标时 ETag 仍随代际变化。这个办法依赖所有写者遵守分配与校验规则。原生接口的观察行为与其公开语义相符。[原生配置并发控制](https://caddyserver.com/docs/api#concurrent-config-changes) · [v2.11.9 实现](https://raw.githubusercontent.com/caddyserver/caddy/v2.11.9/admin.go) · [第一轮结果](<D:/意图协商论文/论文1/GENSPACE-FAIL-01/PAPER1_TOPIC_APPROVAL_20261127/SERVICE_WORKER_DEV_04/native_proxy_20261127-135819/summary.json>) · [独立重复](<D:/意图协商论文/论文1/GENSPACE-FAIL-01/PAPER1_TOPIC_APPROVAL_20261127/SERVICE_WORKER_DEV_04/proxy_agent_verify_01/summary.json>)

## 两个时序边界

**发送前检查后仍可超期。** 新的配对用例让发起方在截止前约 249 ms 通过检查并经本机 HTTP 把任务交给隔离中继。在转发到 Caddy 前受控扣留，直到工程截止期之后。只有发起方检查时，真正的 Caddy PATCH 在截止后约 25 ms 发出并返回 200，业务入口在截止后约 85 ms 读回新目标。在贴近执行点的授权代理检查期限时，转发被拒绝，业务入口保留旧目标。该保护适用于唯一受控转发入口，检查与最后写入之间仍有时间。若要验证硬截止，应将剩余执行及计时误差纳入经过验证的余量。[发起方与执行入口配对记录](<D:/意图协商论文/论文1/GENSPACE-FAIL-01/PAPER1_TOPIC_APPROVAL_20261127/SERVICE_WORKER_DEV_04/forward_delay_20261127-140016/summary.json>)

**新路由可访问时，旧请求可能仍在执行。** 另一个用例先让业务请求进入 A，再暂缓其返回。管理端已收到切换成功确认，新连接也验证了 B 后端和正确图片。释放 A 后，此前的旧请求仍从 A 返回正确图片。它发生在首个 B 读回之后。本案用于判定事件先后。它不提供通常的排空耗时或不间断服务概率。验收应分别记录管理确认、新任务实际走新路由、已接纳旧任务完成或过有效期。若业务要求只采用当前代际结果，消费方还需要依任务及代际检查响应，或在合同中明确等待排空。此次试验验证了区分这些状态的必要性。[在途请求原始记录](<D:/意图协商论文/论文1/GENSPACE-FAIL-01/PAPER1_TOPIC_APPROVAL_20261127/SERVICE_WORKER_DEV_04/inflight_agent_01/summary.json>)

## 还缺什么

已取得实际软件执行端和可独立验证的读回，能够用于 RDINP 履约验收设计。继续研究新机制仍需要以下最小业务证据。

1. **一个实际服务目标及其期限依据。** 具体说明哪类流量需要何种路由或算力切换，以及标准、业务流程或已有配置怎样给出 SLA。同时明确在途请求需要排空、继续返回，还是旧结果不得采用。
2. **一条现有运行轨迹。** 使用同一任务 ID 对齐授权、管理请求、执行端生效、业务读回、实际链路异常及其业务后果。当前注入是为了核验边界，不能估计发生频率或性能收益。
3. **在上述轨迹上做强对照。** 保留原生条件配置更新，再加入已验证的唯一代际、执行端期限守卫和实际业务的既有回退规则。若依然存在可复现的业务损失，才有研究新协商机制的依据。

定位到可提供独立端点的 Ubuntu 主机时，优先将现有 CPU 任务和代理分到不同端点，以保留真实链路与业务轨迹。当前无需 GPU。单纯换机器不会补足缺失的 SLA 或现成故障轨迹。可先向老师汇报协议承诺和执行履约的可复现分离，以及当前已解决的具体场景。
