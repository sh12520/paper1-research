# 面向6G智能体网络的限时意图协商与服务履约保障机制研究

2026年11月27日 · 拟定选题

**拟聚焦的问题**　终端智能体与边缘服务智能体协商一次有截止期的计算任务。当无线链路延迟或丢失提交回执时，终端可能无法判定边缘资源是否已承诺。能否在保留本地回退时间的同时，让边缘只执行仍有效的任务，限制失联造成的资源占用，并提高按期交付的比例？

## 1. 研究依据

RDINP 已实现逻辑资源准入、短期预留、持久提交和提交结果解释。已有两个可复核的案例。提交请求全部被抑制时，终端发布 `RECOVERY_REQUIRED / UNKNOWN`，权威端提交次数为 0，资源仍为 `RESERVED`。提交回复全部被抑制时，终端发布相同状态，权威端已有 1 次提交，资源为 `CONFIRMED`。两例各涉及 10 个逻辑单位。其差别可从原始客户端结果与权威 SQLite 账本直接核对。

这两个案例确定了一个需要处理的事实。**本地必须在截止时间前决定是否回退，但此时仅靠本地状态无法判断远端有没有提交。** 本轮在冻结 C2 的回环 HTTP 与 SQLite 环境通过 5 项关键回归，并新增逻辑配额对照。在总配额和首请求均为 10 单位的配置下，推进权威时钟跨过原预留到期点后，提交请求被抑制的分支可接纳 1 单位的新请求，提交回复被抑制的分支仍因配额占满而拒绝新请求。

上述结果止于逻辑账本。实际任务何时准入执行、已提交但未使用的资源何时释放、回退结果能否按期产生，仍待验证。车路感知归档缺少独立检测任务共享算力的释放和占用记录，本方案从已有可复现的提交与服务衔接问题出发。

## 2. 场景及三个子问题

使用两个主体和一个固定的边缘任务。终端掌握输入、结果截止时间及本地回退方式。边缘掌握一个实际 worker 的准入时段和占用情况。首轮固定一个可重复执行的 CPU 处理任务，记录真实输入字节、任务运行时间、结果及 worker 占用时长。网络条件由同一可重放链路轨迹提供。无线接入使用受控仿真时注明条件，首轮只验证边缘算力承诺，不假设拥有可执行的频谱预留接口。

1. **资源感知。** 定义如何将任务 ID、输入上限、可兑现的算力时段和权威有效期绑定到 RDINP 的业务层结果，区分逻辑提交与实际执行资格。
2. **时限保障。** 从业务截止时间倒推本地回退最晚启动点。以任务结果实际可用作为按期交付依据，单独记录协商终态、边缘执行和回退完成。若已知本地执行与发布的保守时间上界为 $B_{local}$，终端最晚在 $D-B_{local}$ 作出回退决定。
3. **可靠性。** 跨越链路中断时保留真实提交事实，约束迟到请求、重复请求和迟到结果的影响。边缘只有在执行资格有效时才准入。恢复查询只读取同一任务的权威状态。已发布回退的终端保持单一业务结果。边缘执行资格到期与审计记录是否存在分别处理。

## 3. 强基线与首轮实验

| 对照 | 行为 | 用途 |
|---|---|---|
| 原 RDINP 加保守业务适配 | 保留 C2 的确认政策，使用同一任务、相同资源接口和本地回退条件 | 复现现有协议及接口边界 |
| 幂等边缘调用、有限租约和本地回退 | 携带同一任务 ID 提交，超时可同 ID 重放或向权威查询，执行时复查有效期，保留固定回退预算 | 可执行的同任务强基线。包含常规防重复、过期处理和状态查询 |
| 立即本地执行 | 相同输入和固定本地质量档位，无远端调用 | 本地可交付性、时延与质量的参照 |
| 待评估的机制 | 仅在强基线仍反复出现实际失败时，针对已观察到的失败设计与任务截止期绑定的激活或恢复规则 | 验证可独立复核的边际贡献 |

**第一组配对实验**　顺序完成无故障执行、提交请求丢失、提交回复丢失、迟到跨越回退边界、重复请求或恢复查询。两组采用同一任务输入、worker 配额、截止期、可见信息、回退条件与故障轨迹。先固定任务和故障位置，再看结果。注入用于检验协议机制，故障发生率需要单独的实测或文献依据。

**主要指标**　以全部任务为分母，分别报告按期远端交付、按期本地回退、未交付、实际重复或过期执行、未使用承诺的资源占用时长。辅指标包括结果质量或正确性、资源恢复时长、控制消息轮次和字节、端到端耗时。以单调时钟记录任务释放、本地终态、边缘提交、边缘开始和结束、结果到达、回退完成及资源实际释放。

## 4. 理论边界与已有工作

Timed Atomic Commitment 已把决策时限、动作时限和例外状态纳入承诺模型。6TiSCH 6P 也已有双边无线资源事务、超时和确认丢失后的不一致处理。RSVP 已使用软状态预留。A2A 提供任务生命周期接口，RAW 讨论间歇有损无线链路的可靠传输架构。计划检验的是 **RDINP 承诺到实际业务执行之间的具体失效和代价**，把上述机制纳入问题边界及基线设计。现阶段尚未证明有独立的新机制贡献。[Timed Atomic Commitment](https://doi.org/10.1109/12.88481) · [RFC 8480](https://www.rfc-editor.org/rfc/rfc8480.html#section-3.4.6.2) · [RFC 2205](https://www.rfc-editor.org/rfc/rfc2205.html#section-2.3) · [A2A 规范](https://a2a-protocol.org/latest/specification/) · [RFC 9912](https://www.rfc-editor.org/rfc/rfc9912.html)

安全性拟验证实际准入和最终结果发布的条件。时限结论按假设给出。永久失联时只能在终端本地执行条件满足时保证按期回退或发布本地失败结果。远端成功与恢复一致性分别依赖通信可达性和资源状态。实验尾延迟提供性能证据，有界保证需要独立的执行、观察和通信上界。
