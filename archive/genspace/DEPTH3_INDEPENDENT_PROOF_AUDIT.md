# Depth 3 独立证明审计

## 裁判复核了什么

| 义务 | 独立检查与证据 |
|---|---|
| 根覆盖及子分区 | 从 `ClauseHole(3)` 枚举公开类型和参数域。对子句洞分别核对深度、可用角色和各构造器分支。每个可达位置都有完整结构或可复核的开放边界。 |
| 能力剪枝 | 依据冻结注册表、可用角色和公共谓词，重建合法构造器集合。完整输出另用作用域、谓词和合法性规则核对。 |
| 归一化与语义合并 | 独立枚举作用于根和各 `If` 子比较位置的等价分区，重建 packed template 及全异 profile 赋值。只有固定字段、逐单元角色及 profile 关系均相同的模板才共享。字典序代表仍接受所有上下文的原始配方参与比较。 |
| 数学下界 | 独立计算冻结分量下界和带向下舍入余量的联合下界。声称值不能高于复算值。开放区域只有在严格大于 cutoff 分数时才能排除。 |
| 精确分数与同分 | 用冻结公开评分内核重算 binary64 位。完整缓冲合同必须按 `(score, packed_key)` 严格排在 cutoff 后。返回项的合法性、规范键和最小见证另外重算。 |
| 短域穷尽 | 两层分区必须完全闭合。裁判检查无未给出的合法 profile 赋值、无开放结构、无未返回缓冲区。 |

裁判共享冻结 DSL、能力绑定、状态机、规范化、签名、语义包络转移和 FLAT 精确分数定义。它独立实现根覆盖、等价分区、模板赋值、下界算术和终止核对。生产者的优先队列顺序、计数器、前沿最小值或自报认证状态均无权证明覆盖。查询及快照绑定来自外部来源，内容地址只负责标识与完整性。 [证明规范](DEPTH3_FRONTIER_PROOF_SPEC.md) · [裁判实现](results/depth3_proof/symbolic_verifier.py)

## 数据和隔离

验收集合是原封存的 24 个 Depth 3 开发查询。报告分别计入 12 个 rich 查询和五个既有短域。证明生产者使用冻结游标的确定性公开重放和只读快照，裁判仅接收公开输入及待验证的候选前缀和 cutoff 声明。proof 与 checker 均用同一冻结签名和 FLAT public score。每个查询的数据绑定包含原序列化输入、公开奖本、案例归档、执行快照及证明源码摘要。原算法、验证器、协商协议及封存文件保留原字节。 [归档面板](results/depth3_proof/per_query.csv) · [篡改对照](DEPTH3_PROOF_NEGATIVE_TESTS.md)

完整协议回归使用冻结双边路径单独读取同一原序列化开发夹具，核对四个原预算下协议对象、提议历史、状态、验证调用和 proposal 轮数。此过程与只接收公开数据的证明管线分开。
