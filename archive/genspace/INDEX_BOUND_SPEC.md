# INDEX-GATE-01 public score bound

The retrieval index orders the existing depth-one and depth-two V1 structural domain exactly as `results/method_dev_v1/public_search.py` does for `FLAT-FEASIBILITY`. B2's 27 static candidates use the same original verifier and bilateral protocol outside this structural ranking. The two tree variants use the same score and bound. Their partitioning differs.

## Frozen public basis

The query carries the six ordered benchmark state/time capacities, allowed depth, canonical capability names, and the fixed public profile, role cost, and resource-factor basis. It checks that the public capabilities contain the mandatory base roles and match the selected frozen availability pattern. Each indexed candidate consists of its class ID, six active/idle and offload/profile codes, public quality and capability-cost aggregates, mechanism-group count, and public capability/depth membership. The 55 demand templates use the exact operation order in the original proxy. The six-cell mean-quality and mean-cost aggregates use the original per-cell `float64` addition order. Capability roles and depth determine whether a class is in the audited availability set. The original availability audit checked depth2 against required-role mask inclusion for every supported pattern and independently compared depth1 with the reference enumeration. Structural candidates remain subject to the existing V1 limit of one or two mechanism groups. The builder needs only the frozen public basis, graph and audited availability masks. The query adds public capacities and configured depth.

For cell `j` and resource `r`, let `x[j,r]` be the corresponding demand, `C[j,r]` the queried capacity, and `D[j,r] = max(C[j,r], 1e-9)`. The normalized excess is `z[j,r] = (x[j,r] - C[j,r]) / D[j,r]`. The original proxy computes the following, with six cells and three resources.

```text
v = sum(max(z[j,r], 0)) / 18
m = sum(clip(-z[j,r], -1, 1)) / 18
S = v - 0.025*m + 0.02*cost + 0.08*(1 - quality) + 0.01*groups
```

The cost and quality are the frozen scorer's six-cell aggregates. The cost is derived from the active capability execution cost and the sum of its public resource-cost components. Idle cells contribute zero. The score retains the proxy's existing omission of physical surcharge and hard feasibility checks. Exact V1–V4 verification remains downstream.

## Admissibility

For each node `N`, its demand minimum `L[j,r]` is taken across all members by dimension, its `Qmax` is the maximum quality, `Cmin` is the minimum cost, and `Gmin` is the minimum mechanism-group count. The node stores maxima of each demand dimension for tree construction and diagnostics as well. The node lower bound is `S` evaluated using `L`, `Qmax`, `Cmin`, and `Gmin`. These extrema may come from different candidates.

For any member `c`, `L[j,r] <= x_c[j,r]`. Since `D[j,r] > 0`, subtraction of the fixed capacity and division by this denominator preserve the inequality. Each `max(z,0)` term is nondecreasing, so the violation calculated from `L` is at most `v(c)`. Each `clip(-z,-1,1)` term is nonincreasing, so the margin calculated from `L` is at least `m(c)`. Subtracting the positive weighted margin therefore contributes a lower bound to the score. Adding the positive weighted minimum cost and minimum group count preserves this direction. The quality term uses `1-Qmax`, which is no larger than `1-quality(c)`. Consequently `LB(N,q) <= S(c,q)` for every conditioned candidate in `N`. Availability/depth filtering only removes members, so an extremum over the whole node remains a safe bound for the eligible subset.

The implementation computes the same inequality under the frozen CPython/NumPy binary64 evaluation as well. Demand extrema are taken over the exact binary64 template values. Cost and quality extrema are taken over exact binary64 per-candidate aggregates. RAN, FH, and EDGE components are added in the frozen cell order with sequential `np.add.accumulate`. Both violation and margin are divided by 18 only after accumulation. The bound and candidate score use the same multiplication, subtraction, and ordered additions as the reference. Correctly rounded finite subtraction, division by a fixed positive denominator, each monotone clip, and each binary64 addition preserve the relevant ordering. Multiplication by a positive constant preserves ordering. Unary negation reverses it exactly. Thus float64 extrema suffice without rounding padding. Nonfinite inputs or computed scores are rejected. The correctness audit compares candidate score bit patterns to those obtained with the original `_proxy` and FLAT expression.

## Best-first order and accounting

The priority queue orders nodes by `(lower_bound, minimum_class_id)` and leaf candidates by `(exact_score, class_id)`. If a candidate ties a node bound on score, the node's minimum class ID is no larger than the ID of any member. A node key therefore lower-bounds every eligible candidate key lexicographically. Expanding a node inserts its eligible children. Opening a leaf reads the allowed complete feature rows, computes their exact scores, and inserts the head of a locally sorted run. When a candidate is the lowest heap key, no unexpanded node or leaf run can contain a better eligible key. Emitting that candidate and reinserting the next member of the same run gives the exact FLAT order by induction. A depth/capability union of zero at a node proves its entire subtree ineligible. Lean metadata at a mixed leaf enforces individual availability before reading complete feature rows. Extending the returned prefix continues with the same heap state.

An internal node visit means an internal node is removed from the heap and expanded. `NodeVisitRatio` divides that count by all internal nodes of the selected tree. Node bounds computed for a frontier may be counted without a visit. A complete candidate touch means the query reads that candidate's full public score features. Leaf membership IDs inspected and candidates excluded by availability/depth are separately counted. The bound-pruned count at a returned cutoff is the conditioned population still unscored, certified by the frontier ordering at that cutoff. Such nodes can be revisited if a caller asks for a larger prefix. For K greater than the eligible domain, retrieval returns that whole domain in order.
