# Soundness of the depth-2 contextual profile quotient

The quotient changes which syntactic derivations the cursor materializes. It keeps the original publicly conditioned semantic classes, score, tie order, and representative selection. Its scope is the frozen depth≤2 DSL, public registry, scalar profile domain and six-cell interpreter. The baseline graph and index can be used later as independent references. The quotient itself uses no Class ID lookup, graph rows, historical outcomes, or preferences.

## Operator shapes and equality patterns

An operator shape is an AST with its constructor types, typed operator parameters and child order fixed, and one variable occurrence at each `Static` leaf. The allowed shapes follow `src/enumeration.py::public_domain` and `src/engine.py::enumerate_compositions`. Parameters and available canonical roles come from the current public domain. Depth counts only wrapper operators, and `Static` keeps depth zero. Shapes are generated under the original depth cap. The full frozen grammar has at most 91 shapes at depth≤2 and at most four `Static` occurrences in any shape. A shape contributes one symbolic case per equality partition of its occurrences. Even a four-occurrence shape has only 15 partitions. This construction does not expand the Cartesian product of the 27 concrete scalar profiles.

A partition declares which leaf occurrences share a profile and which use distinct profiles. Any complete derivation has exactly one shape and partition. Assign distinct existing public profiles to the partition's groups temporarily to inspect the compact signature. Keep symbolic group labels for the profile bytes that survive into its six cells. This one probe represents the full equality pattern. It is a partial-template construction cost that should be reported separately from actual completion scoring, rather than omitted.

## Why the probe is valid for every assignment in its pattern

Take two assignments of distinct public profiles to a partition's groups. One can be obtained from the other by a bijection on the used profiles. Extend that bijection to a permutation of the shared public profile domain. Consider the effect of this permutation on a normalized child's compact signature.

- A `Static` is valid for every profile in the configured domain. It uses the same canonical base capabilities and scopes, and changes only its active profile bytes under renaming. The frozen profile-support predicates check membership in this same domain. Deadline, quality, and rate magnitudes are not compared with one another in normalization.
- `Sequence`, `Delay`, `ValidFor`, and `Offload` select or transform cells according to fixed time/state and operator parameters. They use the same roles, scopes, predicates and levels for either assignment. An active cell's profile is renamed and every idle cell stays idle. The child footprint joins independently of scalar profile identity.
- A `moving` conditional compares its two normalized child keys. Injective profile renaming preserves equality and inequality of those keys, including profile bytes in cells subsequently cropped by an outer operator. A retained conditional has the same branch selection, whole footprint and cell roles under either assignment. A collapsed conditional may choose a different branch by lexical syntax. The branches already have equal semantic signatures in that assignment, so the choice leaves the resulting signature unchanged. This is the same equality test as `src/state_machine.py::normalize` and `src/compact_semantics.py::CompactEncoder.combine`.

Induction on the shape therefore shows that every assignment in a symbolic case has the same compact prefix, idle cells, offload levels and runtime role masks as the probe. Every non-idle profile byte is the actual value of the symbolic group selected by the probe. The proof uses the original profile domain, public scopes and predicates. It does not justify extending the quotient to new profile-dependent type rules, capacities inside normalization, or a different interpreter.

When an outer wrapper crops a cell, a profile in that cell can still affect a nested conditional's equality test. In `If(moving, If(moving, Static(a), Static(b)), Static(a))`, root dispatch never executes `Static(b)`. With `b = a`, both conditionals collapse. With `b ≠ a`, both are retained and the outer signature includes conditional roles. The same profile is visible in every active cell in both cases. Keeping the leaf's equality relations until after the exact transfer preserves these effects. Operators in branches that never execute may also declare roles and scopes in the contract-wide prefix. Those bytes remain part of the quotient.

## Semantic classes are covered exactly once

Canonicalize each symbolic signature by renaming visible groups in order of their first occurrence in packed cell order. The template key includes every fixed prefix byte, all six idle or visible-group markers, and every offload and runtime-role byte. Compare templates using this full key. Two equal templates have the same concrete signature set: substitute the same distinct profile IDs in their canonical visible groups. A template with a different fixed byte or with a different visible equality pattern has a disjoint concrete signature set. Within a template, two full assignments to the visible groups are unequal in at least one occupied profile byte. Enumerating all-different assignments lazily therefore outputs each reachable signature at most once.

Groups with no occupied cell can be extended independently of the emitted signature, subject to the partition's all-different condition. A recipe is usable when the public domain contains at least as many profiles as its total number of groups. Then any valid visible assignment can be extended to all hidden groups by choosing unused domain values. No actual profile in a hidden group is required in the emitted semantic class. Recipes for multiple operator shapes and equality partitions can be attached to one template without putting duplicate concrete signatures in the scoring queue.

The frozen FLAT structural test counts groups in the whole-contract footprint, with phasing and validity sharing one group. It depends only on the fixed template prefix. Keeping only signatures with one or two such groups matches the original FLAT comparator after capability/depth conditioning. Static B2 continues on its existing path. No public physical verifier decision or bilateral acceptance is needed to construct or filter a template.

## Preserve the representative and final tie order

Each retained recipe records the original raw shape, its full leaf partition, and the mapping between its visible groups and canonical template groups. A visible assignment supplies all visible profiles. For one recipe, reconstruct the least raw `syntax_key` as follows.

1. Reserve every assigned visible profile.
2. Process hidden groups in order of their first `Static` occurrence in the raw syntax. Assign each the unused public profile with the smallest serialized `syntax_key(Static(profile))`.
3. Substitute consistently at all occurrences and serialize the resulting raw AST.

The first raw occurrence of a hidden group is the first character position affected by its value. Whole `Static` serializations are distinct and none is a strict prefix of another in the configured syntax. Selecting the least available serialization at each position therefore minimizes the whole raw key. Every hidden group has the same domain with the same all-different restriction. There are enough remaining profiles for the remaining groups, so a greedy choice cannot exclude a required completion. Minimize the resulting raw key across **all** recipes attached to the template and apply the frozen `normalize` to that witness. Re-encode it and compare its key to the candidate signature before handing it to the protocol. A lexicographically chosen dummy witness is insufficient because ordering among actual recipe instantiations can change with their assigned profiles.

The frozen availability witness builder uses the same raw lexical minimum for depth one. At depth two `src/compact_graph.py::graph_library` retains raw depth-one lexical representatives and chooses the least packed operator/parameter/child-pool token per key. The pool is sorted by raw child text. Replacement by a lexically least equivalent depth-one child preserves the parent's signature through `CompactEncoder.combine` and can only improve the raw parent text. For the frozen operator and parameter strings, token order and raw parent order agree. Thus minimization over all template recipes recovers the same depth-two representative before the existing normalization. The independent comparison should explicitly check this, including equal-score cases and cropped branches.

The score is a function of the instantiated packed signature and current public capacities, with the unchanged float operations. Old Class IDs are ordinal positions of lexically sorted full compact keys, as written by `tools/audit_compact_graph.py`. Comparing those bytes on equal scores preserves original Class ID order without filing or requesting numeric IDs. The search certificate still needs the original admissible bounds and must respect all remaining equal-score possibilities. Template disjointness removes the need to enumerate profile variants of a hidden leaf to settle its witness.
