# Independent information-flow audit (development prototype)

Scope: an independent static inspection of the method's public-search, protocol, runtime and harness, together with five targeted tests in `test_privacy_independent.py`. This is an API/data-flow audit in a trusted single Python process, not an operating-system security boundary against a malicious participant.

- `sanitize_public` uses an allowlist and exposes depth, public cells, profiles, capability availability, resource parameters and role costs; it does not include family, pressure, conflict, hashes, preferences or reservations. The guarded public-object test raises on attempted forbidden label reads. A counterfactual label mutation leaves signatures and all five public strategy orderings unchanged.
- The method entry receives sanitized public data, a public verifier, two agent ports and a public semantic library. Its arguments do not include the serialized instance, seed identity, family, attribution, oracle outcome, weights or reservation dictionaries. The trusted outer harness creates each agent separately before invoking the method.
- Candidate/public-probe ranking contains no private utility inputs. Random ordering is derived from the sanitized public view rather than an instance/private hash or forbidden configuration label.
- Agent choices return candidate IDs; responses return ACCEPT/REJECT and protocol history contains proposal/response messages without utility values. Changing responder weights in a fixed-response test leaves the proposal transcript unchanged. This does not test every possible preference or message history.
- One `PublicVerifier.verify` charges one selected semantic class. The selected-only batch performs exact public V1–V4 checks on at most 16 already-selected classes, then each class is consumed and charged once; public-pass evidence is reconstructed from the exact packed signature. Actual original interpreter calls by the offline harness are separately counted. The targeted budget-2 test observes two selected/charged candidates, rejects oversized preparation and refuses a third call. Public proxy scoring is separately counted and is not represented as private acceptance or exact end-to-end validation.
- The harness reads O1 and per-instance attribution only after all method calls for that instance finish, for offline measurement. The method does not receive those records.
- The B2 negotiation is implemented with local preferences and messages; agreement existence is compared against saved exact B2. Its selected representative need not equal the historical joint-Nash-optimal B2 representative unless the latter is separately supplied as an already agreed public contract. This distinction must be disclosed.

Targeted tests passed 5/5 on the current code at audit time. Before the final integrity claim, rerun after all implementation edits and verify the production runner preserves these interfaces. Positive test outcomes do not prove isolation against Python introspection or arbitrary code changes.

## Final source-bound checks

The final `information_audit_result.json` binds all four method-source SHA-256 values and the method config SHA-256. Nineteen unit tests passed, including exact budget accounting, forbidden-label perturbations, one existing-instance B2 result, B=100/500 prefix behavior, corrected cross-batch alternating turns, and normal/resume/tamper rejection. The fixed global-frequency order O,P,C,D matches the config and source literal. The deterministic historical turn counterexample and the corrected implementation's source-bound retests are retained separately.

For the selected-only public V1–V4 optimization, 924 generated legal candidates over 48 existing PILOT public fixtures matched the original reference verifier's first-failure layer and, on success, action and per-cell cost evidence. Three synthetic public-only capacity boundary tests also matched; they are not generated benchmark instances. Across all 17 frozen availability patterns and both depths, no indexed generated class failed the fixed-registry V2 check, and the complete rich graph contained no V3-invalid semantic class. These checks do not prove behavior for arbitrary invalid ASTs or alternative registries.

The integrated packed/heap backend and retained pre-integration reference matched in 80 fixture/method comparisons (16 existing PILOT fixtures, five methods, B=100 and 500), including complete proposal/response histories and non-timing outcomes. An additional existing instance matched at all five budgets through B=10,000 and 9,998 protocol messages. Tests explicitly blocked full-graph `FastEvaluator.evaluate`, benchmark seed derivation and random instance generation. Internal batch operations, per-candidate verification units and offline original-interpreter checks are separately recorded; every selected candidate is charged once. Sample equivalence is not a proof across all possible instances.
