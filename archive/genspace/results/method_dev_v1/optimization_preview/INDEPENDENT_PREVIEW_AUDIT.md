## Interpretive and provenance limits

Agreement, selected class/witness, verified-candidate count, public probe/ranking counts, search path and proposal/response history matched in the stated differential samples. They may be described as matching **on those samples**, not as verified identical for unsampled instances or all high budgets. Actual method utilities/Nash in the extra index102 comparison were generated by the existing offline validation; the 16-fixture comparison tests the decision path and output, not an independent second private evaluator.

Wall-clock, CPU, memory, cache setup and low-level `state_machine_calls` are implementation dependent and must not be copied or merged across versions as though measured by one backend. `verification_calls` is the charged selected-candidate API count, not the number of calls to the original AST interpreter. Public scoring/precomputation work and offline interpreter checks remain separately reported.

The preview monkeypatch runner is not bound by the reference harness's four-file run manifest: its `preview_protocol.py` and `preview_harness.py` are extra executable sources. Its existing outputs are isolated engineering evidence, not reference-run records. Adopting this backend requires a separately bound source/config manifest and audit, a distinct output namespace, no silent cross-version resume, and explicit handling of timing comparability. Prior reference records remain valid historical evidence but must not be presented as a single homogeneous full-run dataset with preview records merely on the strength of these samples.

The method's information isolation is an API/data-flow discipline inside a trusted Python process, not protection against malicious introspection. Benchmark verification concerns only the frozen abstract benchmark and is not real-network execution proof.
