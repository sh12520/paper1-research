# Statistical scope and methods

- Input is the complete set of 1,920 existing serialized PILOT instances and their original development-method results. The primary target has 842 paired instances. Budgets are candidate verification budgets, with B=5,000 as the main checkpoint.
- Rank and Top-K replay covers all 842 target instances. Percentiles use NumPy's linear interpolation; offline first-acceptable ranks are one-based positions among structural candidates and exclude the 27 static B2 checks. GLOBAL grouped rank differs from its quota-truncated verification ordinal. Top-K group proportions pool candidate appearances, not instances.
- Timing replays cover 96 instances, one already existing seed-index 0 for each public configuration; the target subset contains 37 instances. These are a structured engineering sample, not an independent confirmation set. Median, p90, p95, and mean are reported in the root runtime report. Each phase share is total phase seconds divided by total method seconds within that sample; it is not the ratio of phase medians.
- There are no significance tests, hypothesis decisions, confidence intervals, or claims of generalization in this descriptive, development-only audit. These would answer questions outside this task's engineering scope and cannot turn the reused development instances into independent confirmation data. Differences across configurations and families are dependent on the benchmark design.
- Figures were generated only from already completed audit CSV/JSONL. `make_diagnostic_figures.py` uses the installed Anaconda Python for plotting; the ranking and timing replays used the frozen CPython 3.12.14/NumPy 2.3.5 environment. Figures do not alter any result or introduce new instances.
