# Graph independence audit

The online boundary for `ON-DEMAND-GRAMMAR-SEARCH-01` permits the fixed public grammar, model, registry and explicitly declared serialized development fixture. Each private preference map goes to its own unchanged V1 `PrivateAgent`. The grammar cursor receives public inputs and a request for the next emitted candidate. It receives no verification outcome, utility, feasibility decision, protocol message, historical rank, outcome label or attribution record.

## Worker boundary

[`results/grammar_gate/guard.py`](results/grammar_gate/guard.py) installs a CPython audit hook for workspace file opens. It rejects the frozen semantic graph, graph-backed availability bundles, INDEX-GATE files, historical method data, undeclared fixtures and writes outside the current online output subdirectory. Allowed workspace inputs are the declared serialized instance file, public model configuration and source modules. These include the three frozen V1 source modules needed to preserve scoring and negotiation. The guard also traps the full graph/availability readers and constructors, the compact graph and complete library builders, the legacy exhaustive enumerator and the instance and seed generators. File and call violations increment separate counters and raise before successful execution. Worker output records the full counters and blocked-event list.

The offline comparator is a separate process. It may read the frozen graph and historical outcomes once the online run has sealed its output. The offline comparator can translate a signature to its historical numeric class ID for equality checks. It never gives that mapping, the historical order or an oracle outcome to the grammar cursor.

This is a process-level software audit of the Python paths used by the worker. The guard does not provide an operating system isolation boundary. The launcher and code remain trusted, and the worker has no inherited research artifact file handles. The negative probes verify the file hooks and entrypoint wrappers used here. A passing runtime independence audit additionally requires all formal online output seals to contain zero attempts.

## Exact verifier and protocol bridge

[`results/grammar_gate/protocol_adapter.py`](results/grammar_gate/protocol_adapter.py) supplies at most 16 emitted 49-byte compact signatures to the unchanged `PublicVerifier.prepare_batch` and `verify`. The temporary rows carry the native six-cell encoding and whole-contract role mask. It builds demand and surcharge tables from the same public profile domain and registry rules as `FastLibrary.bind_public_basis`. A grammar derivation within the allowed depth supplies the V1 domain-membership condition. The native verifier checks capability support and predicates, semantic validity, physical loads and public hard constraints. The final witness is checked with the original native witness reconstruction method, including normalized signature, schedule and costs. Neither the packed verifier rows nor the public basis tables enumerate or store graph entries.

The graph writer assigns IDs in ascending compact signature order. The adapter uses the signature bytes as stable identifiers in the original protocol and its private-utility tie-breaking heap. Lexicographic order on those bytes preserves relative class ID order, including utility ties. B2 verifies the 27 static candidates in that order in batches of 16 and 11. B2 success returns before the grammar cursor is constructed. Following B2 failure, the unchanged protocol and its append-only candidate pool receive the next verified batch with the original budget boundaries through B=5,000, including B=1,000. The recorded proposal events use signature hex instead of integer IDs. Independent reference comparison translates the historical proposal IDs to the same signature representation. The final selected witness's utilities can then be checked independently with `verify_instance`, as in the V1 historical harness.

The 3-case Top-K and 9-case bilateral correctness supplements also ran in separate online processes with the same source hashes. All their file-open and forbidden-call counters were zero. Every case payload matched its respective seal before access to the independent reference. The online performance and gate measurements use the original 128-case seal.

## Local guard probes

Fifteen isolated negative probes each failed closed. The probes covered four prohibited file opens and eleven attempts at prohibited reading, construction, enumeration or instance and seed APIs. They were kept out of the measured candidate search. One positive probe on existing fixture `F1__low__high__rich__d1__s11` completed B2 with 27 checks, 18 public-feasible candidates and one proposal. Its selected `Static(0.6, 1.0, 0.5)` witness and utilities matched the historical outcome. The guard counters were zero during this positive probe, and an injected cursor factory raised if called. The positive probe established B2 behavior before structural expansion. The formal guard counters and cross-process seal form the evidence for the complete online run.

## Formal verification

The formal depth≤2 batch sealed all 128 designated case records. The independent preservation check verified the seal, all case bytes, the original serialized case identities and the five bound online source hashes. Each forbidden file-open, loader, builder, enumerator, instance and seed counter was zero. The blocked-event list was empty. The graph independence check passed for this batch, including cases that reached an engineering search limit.

The same check verified 16,544 historical file hashes against the prior FLAT and INDEX audit manifests, replay manifest and serialized index array manifest. It found no missing or changed anchored files and no unexpected files in the protected historical trees. The existing CONFIRM denial remained in effect and `FROZEN_CONFIG.yaml` was absent. See [`results/grammar_gate/preservation_check.json`](results/grammar_gate/preservation_check.json) for the individual evidence fields and seal digest.
