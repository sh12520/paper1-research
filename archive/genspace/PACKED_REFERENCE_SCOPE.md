# Scope of the packed reference used in the full differential

`src.state_machine.verify_instance` is the AST-level benchmark reference. `src.engineering_depth2.PackedEvaluator` is a separate packed-record evaluator used to make a complete 1,394,064-class engineering comparison tractable. It must not be called a direct per-AST reference run. The following is a code-level equivalence argument only for the current fixed generated-instance domain, the audited depth-two graph and the fingerprints to be recorded with the comparison.

The graph contains V1-legal, V3-valid representatives over the fixed three-time/two-state grammar. Its 49-byte keys encode each normalized whole-contract role, required scopes and predicate outcomes; each of six guarded cells encodes idle or profile index, offload level and active role mask. The graph's relation to AST semantics rests on the independent full syntax/key comparison and compact encoding evidence, not on this timing evaluator. Candidate order and graph contents must be checked against the FAST library before comparing values.

For generated ENGINEERING instances with the fixed registry/model basis, all cells have finite nonnegative capacities; profile values and grammar parameters belong to the configured public domains; states contain both `still` and `moving`; reservation support is true; and generated weights/reservations are finite and in the model's valid ranges. In this domain:

- The interpreter's V1 and V3 checks pass for graph witnesses. The packed evaluator checks the valid bit and retains all graph classes as in-domain. Its `public_filter` compares each required role's binding/descriptor compatibility, required scope bits and public predicate bit mask. Those inputs correspond to the interpreter's V2 checks for the encoded normalized footprint. The packed code assumes the configured grammar and public predicates are true; it is not a general evaluator for arbitrary altered public states or invalid ASTs.
- The interpreter computes an active cell's base demand from its profile/offload, then adds costs for its active role set and checks each RAN/FH/EDGE capacity. The packed path decodes the same guard/profile/offload/role mask, uses the same model `demand` function and role registry, and calls the same `hard_check`. Resource and execution cost sums use the same fixed role order. The AST interpreter also checks the validity of capacities in idle cells; the packed path skips idle-cell capacity validation. Therefore equivalence requires the generated-instance guarantee that **every** capacity cell, including idle cells, is finite, present and nonnegative. Outside that guarantee the packed path must not stand in for the AST verifier.
- After V4, both paths call the same `utilities` function with the same active action tuples and per-cell cost dictionaries, then use the same reservation comparisons. The packed path assumes valid finite private parameters; it does not independently duplicate every malformed-preference check in V5.

This argument is conditional on correct decoding, exact fingerprint/basis matching and the stated generated-instance invariants. `tests/test_engineering_depth2.py` independently exercises both paths on the complete two-profile depth-two grammar for a rich and a sparse engineering fixture, but it is not an exhaustive per-AST check on the full 27-profile domain. The required four-family full comparison is FAST versus this *packed* reference; any report must disclose that limitation. Boundary decision and selected-witness equality must be checked exactly under `DIFFERENTIAL_VALIDATION_SPEC.md`.
