# Draft benchmark model specification

Status: proposed pre-pilot model, not frozen, empirical or a real-network execution proof. Each generated instance contains separate serializable public and private records. The instance is generated once and all methods must read its exact serialization. `config.yaml` is JSON-formatted YAML, loaded via the standard library on each generation; model parameter domains and sampling ranges are taken from it, while formulas and fixed family mechanisms are implemented in `src/instances.py`. The model configuration and cost-accounting block are hashed into every public instance. Registry cost metadata is checked against configuration before generation. The model uses no LLM, simulator, TFH data or private-guided candidate generation.

Public fields: family, configuration, three-slot horizon, still/moving state domain, state-time RAN/FH/EDGE capacities, fixed scalar profile spaces, available capability IDs and full registry declarations (including costs, preconditions and effects), finite operator parameter domains, hard constraints and public resource coefficients. The complete private record holds Application and Network weights and reservation thresholds. The public and private portions and full record have separate SHA-256 hashes over sorted-key compact UTF-8 JSON; full instance hash also includes namespace and seed label. The registry is embedded in the public record so any changed registry changes public and instance hashes. Deserialization restores the same dataclasses and hashes. JSON float values are Python's standard deterministic representation, not a cross-language canonicalization standard.

Seed derivation hashes canonical JSON of namespace, family, configuration and seed string with SHA-256, interpreted as a Python random.Random integer seed. The tagged seed identities are disjoint across SMOKE, PILOT and CONFIRM; hashes are not a mathematical guarantee of disjoint numerical RNG streams (SHA-256 collisions remain theoretically possible). The generator defaults to the ENGINEERING namespace; any SMOKE, PILOT or CONFIRM namespace must be explicitly supplied, and every instance retains the namespace. Before the default was corrected, a few unit-test fixture instances used the old default SMOKE label. No SMOKE experiment, summary or outcome was produced. No confirm seeds are instantiated by defining the namespace.

Scalar domains in `config.yaml` form Cartesian products: M0 quality {0.8}; MR {0.4,0.8}; B2 {0.4,0.6,0.8}; MR deadline {1,2} and rate {0.5,1}; B2 deadline {1,1.5,2} and rate {0.5,0.75,1}; M0 deadline and rate each {1}. These intentionally narrow draft domains cannot establish generality. Grammar conditions {moving}; durations and offsets {1}; intervals {[0,2)}; offload {edge}; depth counts operators, with Static depth 0. Sparse capability mode independently removes each of four public structural capability groups with probability 0.5; rich retains all. The static base remains available. Sampling does not inspect utility.

A shared resource model applies across families. For pressure low/medium/high, RAN baseline is 0.92/0.72/0.52 plus one uniform jitter in [-0.04,0.04]. F1 multiplies moving RAN capacity by 0.68, F2 multiplies t=0 by 0.35, F3 multiplies t=0 by 0.65, and F4 multiplies all by 0.72; other multipliers are 1. FH capacity is 0.75+0.1*(baseline+jitter); EDGE capacity is 0.8+0.1*(baseline+jitter), both constant across time/state. Capacity values are rounded to six decimals. These stylized family inputs are deliberately different operational conditions, not measurements. For quality q and rate r, normal demand is (q,0.4r,0); edge offload demand is (0.5q,0.28r,0.5q). All per-slot/time/state hard capacity limits are separate from utility. Additional public hard constraints require at least one active state-time cell, quality >= 0 and deadline <= 2; public reservation_supported is true. Timing, offload, condition and capability checks are specified separately in CAPABILITY_SEMANTICS.md.

Utilities depend on the realized guarded action schedule and the selected-path per-cell role costs, both included in the public semantic signature. A schedule alone is insufficient for utility-preserving deduplication. Inactive cells contribute 0 service. Define Q as sum of active quality divided by all 3×2 state-time cells; L as sum of 1/(1+deadline) divided by all cells; D as mean over states of first active slot / horizon (or 1 if never active); and S as fraction of adjacent time pairs whose (profile,offload) values differ, counting transitions to/from inactivity. Application utility is [wq*Q + wl*L + wd*(1-D) + ws*(1-S)]/(wq+wl+wd+ws). Network mean resource demand R,F,E divides the total realized base demand plus active-path role resource surcharges by all cells. Define C as the number of distinct active (profile, offload level) settings divided by the total state-time cells. Let X be the sum of active-path distinct-role execution costs over all cells divided by all cells. Network utility is 1 - [wr*R+wf*F+we*E+wc*C+ws*S]/(wr+wf+we+wc+ws) - X. Both values are bounded to [0,1] defensively. Resource utilization and soft utility do not replace the hard capacity checks. Complexity is distinct realized operational settings C, not AST size; runtime role costs X are accounted for separately.

Weights are independent uniform samples: Application quality [0.5,0.8], latency [0.1,0.3], delay [0.05,0.2], switching [0.02,0.12]; Network RAN [0.2,0.4], FH [0.1,0.3], EDGE [0.1,0.3], complexity and switching each [0.03,0.12]. Application reservation is U[0.50,0.62] medium and U[0.62,0.74] high; Network reservation U[0.38,0.50] medium and U[0.50,0.62] high. All draws happen after the public record is assembled; no private values feed public structure or enumeration. These ranges are research modeling assumptions; no confirmation conclusion is warranted.

Capability setup/deployment cost is zero for this first benchmark, chosen before any smoke, pilot or confirmation outcome. Each active time/state cell traverses the selected conditional branch and the active local-time path; each distinct capability role on that path is charged once for that cell. Unselected branches and idle cells incur no runtime resource or execution cost. Its per-role resource costs add to base demand in the cell; execution costs add to the network utility penalty after summing over all active cells and dividing by the number of time/state cells. The resource-weighted network utility uses the surcharge-inclusive cell loads. The registry and config contain all role costs. This cost convention is an explicitly chosen abstract accounting rule, not an empirical deployment claim. `If(moving,A,B)` is normalized to the lexically smaller normalized child when A and B have the same public semantic signature; this includes `If(moving,P,P)`. Normalization happens before V2, cost and execution; normalization is part of this benchmark's contract meaning. The semantic signature retains per-cell active role names and costs and the normalized whole-contract capability footprint.
