# Depth 3 前沿证据规范 · DRAFT

## 待证明的断言

对绑定的冻结公共输入、有效深度 3、合格结构语义域和给定 K，证据证明归档前缀恰是按 FLAT binary64 分数和规范键排序的最前 K 条，或已涵盖整个长度小于 K 的语义域。从归档读取的候选和终止字段在此处只定义待验证的断言。证据还需绑定当前执行快照、归档查询字节摘要、公共输入摘要、实际可用规范能力角色和被比较前缀 SHA-256。 [独立裁判](results/depth3_proof/cover_verifier.py)

## `typed-cover-dag-v2`

证据由公共绑定字段、`coverage_k`、根编号和按编号存储的紧凑规则数组组成。一个覆盖证据用最大已证明 K 的边界，可以核对同一归档前缀的较小检查点。大于该 K 的检查点保留缺证或原资源状态。完整原始语法上下文从唯一 `ClauseHole(3)` 根重建。裁判沿每条引用重建目前的类型、剩余深度、完整位置环境、归约参数和能力条件。节点编号为数组稳定偏移。规则共享不会把两个引用上下文视为同一个具体合同。判断每个入边时重新核对该规则和对应上下文。

| 规则 | 紧凑记录 | 独立检查 |
|---|---|---|
| 展开 | `["E", child_ids]` | 按固定前序选择第一个未决合同洞，重建所有静态参数值和每个构造器的每个离散参数。保持原先的上下文与剩余深度。要求每条派生子区间出现且按顺序对应一个子证明。 |
| 完整候选 | `["C"]` | 输入已为闭合同。用冻结合法性和紧凑语义重新得到 key，独立按原 FLAT 公式评分。规范代表仍由所有相关合法语法推导的最小 raw witness 决定。 |
| 下界排除 | `["B", claimed_bound]` | 裁判从完整当前上下文重建冻结语义包络和局部下界，要求声称值以 binary64 位一致并严格大于最大证明检查点的截止分数。 |
| 能力不可能 | `["I"]` | 现有明确构造器的全部必需能力与注册表及本查询可用角色比较。缺失必需角色已使其所有延拓被冻结原始语法排除。 |
| 等效合并 | `["M", complete_target_id]` | 当前 term 已闭合，目标必须是根下实际到达的一个无歧义完整语义 key。重新计算源、目标 key 并检查相等。源的 raw witness 仍参与代表选择。开放部分合同、同包络状态或未到达节点的合并均拒绝。 |
| 结构空域 | `["X"]` | 重算当前上下文的最大可能结构机制组数，须为 0，故没有可进入此次排序的结构类。 |

静态份额涵盖每个原 profile。语法的原始笛卡尔空间可以有归约后语义重复；入口合法性与语义身份分离审查。通过覆盖证明，在每个有入边的位置使用检查过的规则，根的所有合法延拓必落在闭叶或独立排除分支。共享的闭叶规则记录只有常量状态类别，其当前语法、参数和能力来自该入边。所有记录必须可达，循环边、缺参数、少孩子、多余记录、重复 JSON 字段、非有限分数均拒绝。文件与上下文消费设上限，达到时记录缺证或大小超限。

短域穷尽必须没有下界排除，独立收集并按规范 key 去重后查得准确总数。全长证明允许排除后序空间；同分的却必须继续展开。排序比较先用精确分数，再用规范 49 字节 key。合并与同分判断都覆盖归一化后的重复合同，不忽略可能改写代表的 raw witness。

## 共享冻结语义与独立算术

可信计算基础包含冻结类型规则、公共参数域、能力绑定、`AbstractSemantics` 的语义包络转移、规范化、packed key 编码及向量原 FLAT 评分公式。双方共用这些语义定义。独立裁判的根与子分区重建、支配边界检查、证据消费、叶去重、顺序和短域判断不调用 `DepthCursor`、`GenericCursor`、任何搜索堆或已认证接口。

下界复核基本项按原 binary64 计算顺序，在 demand 下界、quality 上界、cost 下界、最少组数构成的放松状态上重算。资源 excess 正部单调随 demand 上升，margin 对 demand 非增，quality 在分数中为负方向，cost 与 groups 为正方向。同顺序有限 binary64 操作保持这些单调关系。独立 joint 项对每个单元的实际可达 profile/offload 或 idle 取最小贡献，再加最低角色成本与组项。它放宽跨单元一致性，涵盖每个真实完成分支。joint 表达式中不同的重新结合顺序采用冻结的 `2^-38 × (32 + 32 V + 12 A)` 向下余量。V 和 A 分别取该公开查询的最大有限 violation 分量和完整非负角色掩码成本。两个表达式以同一组已经舍入的资源项和同一 binary64 系数为输入。加法、除法与计权先后操作数各少于 128 项，绝对系数加权输入量受括号内的尺度控制。标准 `γ_128=128u/(1−128u)` 误差界与最后的误差估计／减法舍入均被该余量覆盖。常量尺度项覆盖有界域中的小分量。两安全下界的最大值仍是安全下界。边界必须是严格 `LB > cutoff_score`，等号拒绝。 [冻结下界分析](GRAMMAR_BOUND_SPEC.md) · [冻结包络转移](PARTIAL_CONTRACT_ABSTRACT_SEMANTICS.md)

## 证据限额与适用范围

Raw v2 从全部原始语法推导检查根覆盖，所以适用正对照和一般缺证诊断。开放状态语义归并需要额外的上下文证据，不能用 envelope 相同取代。实际 rich 域是否能在限制内提供全覆盖取决于测量。若证明过大、过慢、不独立或不健全，报告对应资源／验证状态，并保留未认证检查点。

## `symbolic-typed-cover-dag-v2` · DRAFT

该格式把公开的根空间分为两个可检查层次：带类型的构造器结构分区，以及归约语义模板的公开 profile 赋值分区。序列化对象由 `format`、`binding`、共享 `nodes` 池和按 K 标记的 `checkpoints` 构成。`binding` 由调用方从受信任的冻结输入和归档重建，包含公开查询与有效深度、归档输出、能力环境、算法及执行快照绑定。生产者记录冻结搜索器在确定性公开重放中的检查点。它读取搜索循环已有的队列字段，保留已完成编译的语法描述，并按内容地址共享记录。裁判从公开根独立展开并检查记录是否构成完整分区。节点哈希用于绑定与复用，不能推出分区覆盖、语义合并或下界正确性。 [记录器](results/depth3_proof/native_symbolic_producer.py) · [独立裁判](results/depth3_proof/symbolic_verifier.py)

| 记录 | 节点内容与核对方式 |
|---|---|
| `OPEN_SHAPE` | 部分语法及其各洞剩余深度、声称的 binary64 下界。裁判在自身构造器树上匹配该位置，重建能力条件与完整上下文的公开包络。 |
| `COMPILED_SHAPE` | 完全确定的构造器、逐节点公开离散参数及待赋值的 profile 位置。裁判在自己的树内到达该叶，重新生成所有相关 profile 等价分区和模板。 |
| `TEMPLATE` | 固定 25 字节签名前缀、六个单元的 idle／可见变量标签、offload 等级、活动角色掩码、可见变量数及结构机制组数。裁判核对其与独立生成的模板完全对应。 |
| `OPEN_ASSIGNMENT` | 模板、已赋值的互异 profile 前缀、下一个 profile 的非空候选掩码及声称的下界。裁判重建并核对赋值包络及所有掩码的分区关系。 |
| `COMPLETE_CANDIDATE` | 已具备具体赋值但仍留在缓冲区的模板、完整赋值、规范 key 及精确分数。裁判重新构造 key 并用冻结公式重算分数。 |
| `EMITTED` | 已返回的规范 key、精确分数和规范化后的代表合同。对照同一归档前缀逐行检查，并单独完成合法性、评分、排序与代表复核。 |

**根覆盖。** 以 `ClauseHole(3)` 作为唯一根，在每个上下文中前序选择第一个未决合同洞。裁判枚举 `Static(ProfileHole)` 和所有受当前角色与剩余深度允许的构造器及参数值。公开类型、作用域和正谓词约束由冻结注册表和 `PublicReference` 确认。不可用构造器没有合法派生。裁判对无可能结构机制的分支单独重算并证明其为空。其余分支必须遇到有证明下界的开放语法位置，或到达提供全部 profile 分区的完全构造器结构。多余、不可达或相互覆盖的声称位置失败。该过程没有把生产者曾经访问的节点集合当作完整根空间。

**分区与合并。** 给完全构造器结构中的 `Static` 位置按出现次序编号。用冻结状态机独立检查根的六个观测单元，以及每一个原始 `If` 的两个子句分别作为根时的六个单元。后者覆盖可能受父分支掩蔽却会影响 `If` 等价规范化的活跃位置。对所有这些位置生成限制增长串，每一串唯一表示一种相等关系。公开 profile 谓词与能力不区分合法 profile 值，调度传输不访问未观察位置的 profile。保持相等关系的注入重标号保留子签名的比较结果、规范化的条件折叠、静态能力足迹、活动角色和有效性，只更改存活的 profile 字节。这一性质由子句上的结构归纳得到，在比较完整 `If` 子签名时需要上述额外观测。裁判按照每个分区的冻结 compact encoder 重建模板。只有包含全部固定前缀与单元字段、可见组关系也相同的模板可以共享具体赋值域。不同模板的具体 key 集合不交。全部规范化前的重建配方仍参加代表选择；对隐藏但相关的组，从剩余 profile 中按首出现次序取最小 raw key，在充分的互异 profile 数量约束下保留延拓。完全无关位置独立取最小值。比较所有配方实例化后的 raw key 后才规范化代表。 [冻结语义等价论证](GRAMMAR_DEDUP_SOUNDNESS.md) · [相关位置及深度 3 推广](DEPTH3_SOUNDNESS_REVIEW.md)

**赋值覆盖。** 每个重建模板在已赋值前缀为空时允许完整公开 profile 域。对任一已赋值前缀，开放记录的掩码与实际存在的下一值子分支两两不交，并集必须正好等于除去已用 profile 的域。已完整赋值的叶必须是独立重建的精确缓冲合同或已输出合同。每个分区在足够多 profile 时有隐藏变量的互异延拓。根覆盖与该赋值覆盖结合，得出每个合法具体合同的规范 key 要么对应已计入的具体叶，要么由一个已检查下界的开放区域涵盖。

**边界。** 开放构造器位置使用其完整状态—时间—资源包络，开放赋值位置按模板逐单元重建 profile 掩码、固定等级与角色。裁判使用上节独立 binary64 算术核对。任何未完整赋值的区域，其可独立验证的下界均须严格大于截止分数。分数相同的完整缓冲合同与最后一个输出比较规范 packed key。它们仅在严格后序时保留在缓冲区。此条件也保证无法从开放区域再找到一个同 key、同分数但 raw witness 更小的语法推导。短列表只有在两层的全部开放区域及缓冲区均为空时才能认定穷尽。三个检查点共用节点池，裁判对各自的前沿和前缀分别核对。资源中断只保留已真正证明的检查点。

**可信边界。** 裁判共用冻结构造器、角色绑定、状态机、规范化、紧凑语义编码、抽象转移和 FLAT 的精确评分内核。它独立实现搜索空间覆盖、等价分区生成、赋值覆盖、数值下界复核、截止判断和代表配方检查。裁判没有按优先队列重跑搜索，也不使用私有输入、历史成功标签或完整深度 3 语义图。两层证明是否覆盖固定开发面板和实际资源消耗由独立审计记录。该规范待面板验证，仍处于准备态。
