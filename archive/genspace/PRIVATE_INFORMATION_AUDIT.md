# Private information audit — ORACLE-RUNTIME-CLOSE-02

The signature, normalization and experimental semantic DP receive public information only: grammar/profile/time/state, registry descriptors and public predicates. They do not receive private utilities or reservation thresholds. Instance records serialize public and private sections separately; the public hash covers registry declarations and model configuration hash, and the paired runner consumes one serialized instance for all methods. Provider-ID substitution and reduced-domain all-private-field noninterference are unit-tested.

The FAST path loads the fixed public semantic graph, then applies public role/scope/predicate filtering and public capacity/hard-constraint checks before inspecting private preferences at V5. It evaluates private utility only for V4-feasible candidates; it does not use utility or reservation to generate or truncate the candidate set. Representative utility maximization happens after public candidate construction and feasibility checks and never guides generation. The execution snapshot and public model/registry compatibility are checked on load, with mismatches rejected; invalid private preference inputs also fail closed.

Engineering differential evidence covers all 1,539 rich-graph depth-one classes on each of four F1–F4 fixtures against direct AST interpretation, including separate capability-conditioned generated masks and lexical witnesses. All 1,394,064 depth-two graph classes per fixture were compared against the packed reference, including rich and sparse settings: generated membership, public eligibility and V2/V3/V4 masks matched exactly; reached-V5 utilities and Nash values were bit-identical, and acceptance matched. The depth-two numeric report does not independently assert lexical-witness equality; separate conditioned syntax streams and final-snapshot rechecks cover the relevant patterns and selected representatives. The ±1 ULP engineered reservation checks matched the AST reference for one candidate. See `DIFFERENTIAL_VALIDATION_REPORT.md` and `results/engineering/conditioned_final_differential_provenance_v2.json`. These checks do **not** independently prove noninterference for every possible public/private input. The full depth-two numeric reference is packed; its fixed-domain assumptions, especially complete finite nonnegative capacity cells even when idle, are in `PACKED_REFERENCE_SCOPE.md`.

The earlier same-public/different-private noninterference test changes all private fields on a reduced domain. An additional ENGINEERING-only full-domain check is recorded in `results/engineering/full_provider_noninterference.json`: for one generated public instance, all private fields were changed within their configured ranges while the public record remained fixed. Across all 1,394,064 graph records, the in-domain, V2, V3, public-eligibility and physical-feasibility arrays were identical, as were the signature, structural-novelty and mechanism arrays. V5 values and acceptance were not required to stay equal. This uses one shared read-only graph; the equal key hashes demonstrate unchanged reused keys, not an independent re-enumeration under each private record. It is evidence for this fixture, not every possible preference or public instance.

The same engineering audit replaced the available `set_quality` provider with a different ID and provider name carrying equivalent type, predicate, effect, scope and cost descriptors. All 1,394,064 conditioned generated-universe, domain, V2/V3/public/V4 and acceptance array entries agreed; utility and Nash arrays were bit-identical, and the conditioned selected representative, novelty and mechanism arrays agreed. Its scope is one role substitution on one public fixture, not all providers. The standalone helper, graph and final execution snapshot were fingerprinted before and after. The 17 capability-pattern indices are publicly precomputed and the snapshot binds their manifest; retained syntax-stream rechecks independently cover the actual tested 31/26/19 patterns and negative-control pattern 0. Changes to private data must not change public eligibility or the semantic library; only V5 values, acceptance and representative selection may change.

ENGINEERING, SMOKE, PILOT and CONFIRM are distinct namespace-tagged identities. Early unit tests used the legacy SMOKE default for isolated fixtures before it was changed to ENGINEERING; they did not execute SMOKE-01 or collect study outcomes. No PILOT/CONFIRM seeds were generated. The experimental runner blocks all research namespaces. Source, config and dependency fingerprints in the fail-closed execution snapshot are separate from a frozen research configuration; `FROZEN_CONFIG.yaml` has not been created.
