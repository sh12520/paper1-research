# DAIR-V2X-C 独立验证 · 锁定方案

锁定日期 2026-11-24。锁定前未运行任何独立验证帧。46 帧训练示例仅用于流程检查和在此冻结操作参数。

## 面板和推断

- 使用 AIR-THU 官方 cooperative val 的全部 1,783 个车端 ID，原列表见本目录 `val.json`。通过官方 cooperative/data_info 映射到车路对，再用官方路侧 batch_id 划分连续场景。场景内按时间戳、车端 ID 排序。预检记录全部缺失文件与原因。完整面板是主分析。若发布源缺图，另保留按文件可用性预先生成的配对面板，报告范围和场景覆盖，并作为次级结果；禁止用模型输出挑帧或拼接 V2X-Seq 图像。
- 主指标是官方 BEV AP@0.7，辅助为 AP@0.5。记录每目标 IoU/匹配、逐帧 TP/FP 和置信度排序。连续路侧批次为分析与配对 bootstrap 的抽样单位。以种子 303 对完整批次配对重采样 2,000 次，每次重算 AP。少于 10 个有效独立批次时仅报告描述性差异，证据等级不足。
- 主比较在 256 KiB、100 Mbps、RTT 10 ms、截止 50 ms。次级预算为 128、1024 KiB，再报告 100、200 ms。链路模型沿用已实现的串行单向传播 RTT/2 和 5 ms 观测、2 ms 选择、1 ms 请求处理、3 ms 接收/融合；记录实际 CPU/GPU 时间另列。100 Mbps / 1024 KiB / 100 ms 用作旧回退规则复核，不用于调参。
- 最小有意义净改进预定为绝对 AP@0.7 +0.010，且配对批次 95% 区间下限高于零、至少有目标级恢复证据。该阈值高于训练例上二值反馈的 +0.0053 和观测参照的 +0.0035，作为筛除微小收益的操作门槛，未宣称已达到应用安全门槛。主比较失败时，次级设置只能作为补充。冻结后禁止用此验证集反复调参。

## 动作、协议与归因

- 固定 TMC 官方 DAIR 异构权重、骨干、检测阈值及扫描网格。选择同一网格的发送侧 cell 子集，使用同一多尺度掩码展开与融合。原生结果按原生量计，统一比较使用 float32 向量、逐尺度 uint16 索引和每消息 16 字节头；共同位姿预先提供。单比特整网格、两比特及 128 个 uint16 索引的稀疏反馈分别记录。多消息重复向量或索引按实际模型发送次数计费。
- 统一比较预留稀疏请求字节后，按总预算的一半发送第一包主动特征，剩余预算用于补充。串行请求先到发送方，才选择数据。并行组主动首包和基于本地观测的请求分别在双方就绪时发出，按全双工独立方向传播，发送方两份数据在同一方向串行占用链路。后反馈组在首包完成融合后启动请求，需求保持为本地预测，隔离时序本身的影响。首包与联合包分别用真实融合前向检查；只允许完整应用消息参与检测，包内截断不假设可解码。补充包若迟到，保留已经完成的首包检测。整包若迟到且没有可用首包，回退已完成的本地检测。
- 观测参照 A 用双方模型预测图的信息价值启发式，无 GT。候选集合包含原主动动作、同一预算的双端评分动作与离线目标区域替换。GT oracle B 只在事后从有限候选中选 AP@0.7 最优，平局按 AP@0.5，保留原方案。C 为可部署的本地稀疏反馈。并列报告目标恢复和整体 AP。目标归因分别标记需求预测、发送方价值、预算、融合、分数排序、迟到及原因未定；完整因果证据链不足时保留原因未定。
