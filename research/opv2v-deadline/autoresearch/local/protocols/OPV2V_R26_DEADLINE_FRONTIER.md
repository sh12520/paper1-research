# R2.6 完整检测截止可行性边界

80 帧 OPV2V 开发面板、16 场景、BlindMap TMC epoch 37 全 LiDAR、原检测阈值、256 KiB 应用层上限、100 Mbps 共享上行和 10 ms RTT。扫描 35、40、45、50、55、60 ms。沿用 R2.5 的模型包释放与单程 5 ms 传播，不变更发送顺序或感知特征。所有 R2.6 回执、图和决策写入 `results/opv2v-r26/`。

| 组 | 完整检测流程 |
| --- | --- |
| A 原始完整计算 | 保留 R2.5 原分片与计算。尾包到达后集中解码、重建、完整推理。复用 80 帧真实同步计时。 |
| B 接收—计算流水线 | 保留相同原分片，各包抵达即解析、搬运和散写，完整输入才启动模型后半段。复用 R2.5 的精确时钟。 |
| C 流水线＋重复特征去重 | 采用已实际重序列化的 80 个精确去重消息束，在与 B 相同的接收计算路径实际执行并实测。仅删除已收到且逐字节等值的粗尺度坐标和值。保留所有头部、细尺度、相对包顺序、发送准备与传播。 |

首帧验收计入同一冻结面板，并在后续复用。C 的全状态须对照原消息重建，从索引和原始张量、粗权重和多尺度融合到候选、框、分数、方向、类和 NMS 全部按状态逐值核验，且与封存完整检测一致。逐包实际 CPU 解析和 GPU 搬运/散写及完整接收路径进行 CUDA 同步测量。三个重复按墙钟排序并采用对应中位整次及其阶段时间戳。任何必要回执缺失或差异未解决均不发布正式 AP。

每个截止以整帧已完成的融合检测为成功。迟于截止时保留原本地回退，单列全 80 帧的可用输出 AP 及 TP/FP/FN。完整协同输出比例、已完成完整输出评价及部分协同输出相互独立。A/B/C 均无部分触发，C 只变更序列化和抵达轨迹。测时工作包括原始时间戳、CPU 后处理和 CUDA 阶段事件。队列、依赖和资源时间使用实际阶段与冻结到达的因果回放，CPU/GPU 区间分别取并集，物理链路与并发道路部署未测。

从 80 个逐帧完成时间的第 1、40、72、80 个次序统计量确定首次、50%、90% 和 100% 的最小 Deadline。对整体 AP、覆盖率差和完成阈值保留 2,000 次按 16 个场景配对的 bootstrap（种子 303、95% 分位数区间）。配对主要检验 C−B 去重复贡献、B−A 流水线贡献及 C−A 合并收益。45/50 ms 为本次判定联合资源研究的两个预定开发点。C−A 在任一点的完整检测率配对区间下限高于零时，记录联合资源研究候选，同时查看 C−B 和 B−A 是否支持机制归因。人工调参、复杂调度、双边协商及 R3 暂停。

输出五张独立图及机器可读数据。阶段结束先审计全部过去 OPV2V 使用记录，再从匹配的官方权重、预处理及未用过的独立场景中确定确认方案。用实际测得的完整接收路径和固定链路进行后续狭窄的通信与计算预算诊断，保持正式 100 Mbps 主比较原样。
