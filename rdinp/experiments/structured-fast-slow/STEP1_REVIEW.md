# Step 1 修正复算与快切归因

首批四组对照保留在 [r01 结果](STEP1_REPORT.md)和本地提交 6954a87d。这里的 r02 使用相同 81 个配置、10 个种子和 810 组配对输入，每组有 75,330 个已释放任务。逐任务验收覆盖 301,320 条记录。[核验结果](evidence/step1-20261128-r02/AUDIT.json)

复核发现，r01 会把队首任务之后的作业也计入其等待时间，可能触发多余降档。r02 按队首已取得空闲槽位处理。终端收到带有队列快照的回执后才决策，每份回执增加 32 模型字节。被动重协商可复用边缘已收到的同任务主档图像，在收到新代际回执后发送 64 字节启动请求，实际记录到 2,244 次此类请求。[实验说明与复现](README.md)

- 带本地兜底的三组仍全部按期。结构化方案边缘交付率为 67.12%，比修正后的被动重协商高 9.22 个百分点，比静态回退高 17.82 个百分点。
- 相对被动重协商，结构化方案每任务减少 0.52 轮、16.11 ms 和 108 控制字节，平均效用高 0.0078，探索性配对 95% 区间为 [0.0064, 0.0089]。相对静态回退，效用高 0.0116，区间 [0.0094, 0.0137]，每任务多 520 控制字节和 13.71 ms。

- 将已交付轻量档的质量重新计为“本地质量加上原轻量质量溢价的比例”，保持任务轨迹和全部交付档不变。相对被动重协商和静态回退的平均效用分别在保留约 60% 和 71% 溢价时持平。该敏感性只反映用不同业务质量口径记分对同一批结果的影响。
- 原始 5G-LENA 前传平均忙时不足 0.55%，本轮压力来自受控空口扰动和边缘队列。实际业务的质量阈值仍需单独验证。

## 同菜单试验中的快切贡献

四个组合使用相同结构化消息、回执快照、任务轨迹和本地兜底。只改变是否允许初始准入轻量档和是否允许承诺后的切档。完整结构化版的 810 份逐运行汇总均与 r02 原结果逐字段一致。

| 初始可准入轻量档 | 承诺后可切档 | 平均效用 | 边缘交付率 |
| --- | --- | ---: | ---: |
| 否 | 否 | 0.7719 | 49.37% |
| 是 | 否 | 0.7713 | 57.06% |
| 否 | 是 | 0.7823 | 59.50% |
| 是 | 是 | 0.7832 | 67.12% |

在已有同一菜单与准入规则的条件下，允许承诺后切档的平均效用增加 **0.0119**，探索性配对 95% 区间为 **[0.0106, 0.0132]**，边缘交付率提高 **10.05 个百分点**。按截止期聚合全部其他因素时，400、600、800 ms 下的效用增益分别为 **0.0228、0.0068、0.0061**。只开放初始轻量档准入而关闭快切，整体效用变化为 −0.0006，区间 [−0.0025, 0.0012]。紧截止期下初始多档准入也有用，在 600 和 800 ms 的这组数据中作用方向变为负。四组合共享模拟模型和开发样本，结果用于区分机制及其交互。

这样得到的原型验证重点是，在同一份已承诺的菜单里，队列或无线条件变化后能否少一轮交互、按期采用轻量档，且保持回执与代际校验。下一步是否接入正式 RDINP 由作者审阅首轮结果后确认。
