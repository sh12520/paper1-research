# RDINP 接入实际 CPU 任务的一轮开发对照

本轮采用冻结的 RDINP C2 控制面，新增独立环回服务实验。研究问题是在一次固定任务中，权威端已经提交而应用端缺少回执时，能否用常规同任务状态查询获得结果，并减少因回退而闲置的执行许可。

## 在运行前固定的口径

- 三张本机 scikit-image 随包样图。Pillow 实际执行灰度转换、模糊、边缘检测和 PNG 编码。边缘输出为 512×512，端侧回退为 256×256，逐个输出按模式核对 SHA-256。输出分辨率是本实验两档的定义。它不能替代感知准确率。
- 每个任务 800 ms 应用截止，550 ms 时截止采用边缘结果并开始本地回退，预留 250 ms。三者是工程试验设定值。计入控制面请求、数据发出、工作线程计算、返回校验及最终发布。C2 原有秒级阶段计时保持原样，应用回退不等待 C2 终态。
- 三种方法在同一输入和故障规则下轮换。C2 原确认策略、C2 加同一权威的只读查询、幂等租约调用加状态查询。前两者使用同一冻结 C2，后两者的查询访问同一个类型的边缘执行许可。幂等方法是最小可运行的功能参照，使用环回 JSON 与令牌，未对齐持久化签名和故障恢复能力。完整协议性能排名不在本次证据范围内。
- 4 种消息条件。正常、首个证明回执丢失、所有提交或授权回执丢失但状态可查、所有相关回执丢失且状态不可查。故障在应用层定向注入，既非无线包故障率，也不把这些条件作为概率分布。
- 经授权的同一个实际 CPU worker 消费单一任务。未使用的执行许可到期释放。已开始的工作完成后释放。已存 C2 逻辑提交与此执行资格分开。每个正式计数只用一次由程序冻结的任务输出。对过期令牌尝试使用、重复启动、错令牌单做工程负对照。
- 输出事件按同一主机单调时钟记录。发布延迟从任务释放起计。控制和数据字节是可观察 HTTP 应用消息体字节，省略协议头、内核重传和已抑制响应。CPU 任务、实际 socket 和计时属于实测，链路故障为注入。本轮独立于任何历史确认数据。

## 事先规定的解释

优先逐条件查看 3 个同输入配对的边缘按期结果数、回退数、未交付数、未使用许可持有时间和实际工作开始次数。仅作工程描述，不做显著性检验。若 C2 加同任务查询和幂等租约基线消除仍可查询时的回退，具体情形已被常规措施覆盖。若权威查询也不可达，观察到的差距反映信息条件，不据此声称增加交互可解决。继续新增机制前需要独立的真实业务或链路证据及相同保障能力的基线。
