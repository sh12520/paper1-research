# RDINP 会话多档许可原型实测

对照测量真实签验、执行与采用。两端是本机独立进程，HTTP 绑定环回。受控链路在实际请求和响应的入口按有序服务时间注入等待，历史前传轨迹及 810 对仿真保留在 Step 1。[协议规格](../../protocol/permit-v1/README.md) · [Step 1 证据](../structured-fast-slow/STEP1_REVIEW.md)

## 实验口径

- 从已校准的三张 scikit-image PNG 生成真实 512×512 和 384×384 上行图像，边缘计算使用冻结的 Pillow 边缘检测工作负载。256×256 在端侧实际执行。计分用真实采用的边缘图与主档参考图之间的软 Dice 相似度。错过截止或没有采用结果的释放任务记 0。
- 400 ms 从固定外生释放时刻算起。边缘结果必须严格早于 345 ms 被验签并采用。端侧从该边界开始本地兜底，计算和等本地执行器的时间仍计入 400 ms。两组共享队列快照的获取、有效年龄、因果链路采样、预选档规则、两槽限制、任务图像和固定的上下行限速事件。
- 正式配对使用三种链路条件、各四个确定性释放配置。每对有 16 项任务，由两个终端在两代会话许可内发出。每代许可可用四次。任务释放后实际签发或续签，复用许可等待也计入各任务的时间。两组交错先后。服务进程在释放前完成同一图像处理库预热。许可、队列查询和任务发送使用实际签名报文。
- 结构化策略允许边缘在授权的条件满足时从主档切到轻量档。强反应式对照可通过相同快照预选轻量档，在同一边缘规则建议主档上传后切档时，可直接批准缓存输入的轻量执行，计入一次签名选择往返。无需重新上传同一任务的图像。逐任务 C2 四阶段只用于测旧控制面的开销。
- 预定时限检查用相同 400 ms 场景、持续降半链路和九个释放分别测上传前选轻量及上传完整主档后用轻量执行。使用 345 ms 减去端到端时长 p95。后一路径估算余量非正时，结构化策略收窄为上传前选档与上传后超时回退。路径测试样本单独保存，正式配对从未读取其效果分数。
- 记录单调时钟同机各边界、实际环回 HTTP 消息体字节（含四字节帧长度，HTTP 头另计）、模拟链路调度尝试、控制签发与验签、许可确认数、增补选择消息、按档采用、边缘计算及其排队。回执异常由独立验收矩阵受控注入。测量范围为本机受控环境。
- 统计全部释放任务上的逐任务配对效用差。按场景与种子整次运行重抽样，区间用于表述不确定性。效用已包含真实控制开销造成的结果变化，控制字节与时间按整个会话和每个释放任务分别报告。安全或完整性失败必须修复后复测。完整、安全、可配对的净效用差不大于零是科学停止线。

## 复现

从仓库根目录运行。提供标定用的原始图像目录，程序会核对三张图像的 SHA-256。输出是新的运行目录。脚本安装锁定依赖，执行故障矩阵、独立 C2 成本对照、400 ms 配对和自动门禁。Step 1 直接读取封存数据。

~~~bash
python -B rdinp/experiments/permit-prototype/reproduce.py \
  --assets /path/to/scikit-image/data --out /path/to/fresh-rdinp-run
~~~
