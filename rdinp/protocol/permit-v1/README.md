# RDINP 会话级可复用多档许可 v1

适用范围为同一主机上的独立端点、同一单调时钟和受控链路注入。会话签发、验签、消息传输、边缘队列及图像处理均执行真实代码。跨主机部署需要另外定义时钟误差和信任配置。

## 签名与消息

签名载荷的 `revision` 为 `RDINP-REUSABLE-PERMIT-1`。本版本复用已冻结 C2 的严格整数 JSON、P-256 ES256 签名和钉扎验签组件。底层 JWS 保护头保留载体标识，签名覆盖独立版本和闭合消息模式。测试端点使用新生成的独立测试钥匙。每次封装绑定发送方、接收方、消息类型和载荷 SHA-256，应答绑定请求签名头的 SHA-256。与原 C2 使用不同的逻辑消息模式和服务路径。

通过 HTTP 将签名 JSON 与原始二进制图像放进同一请求。前置 4 字节给出签名头长度。应用层控制字节等于签名头长度加 4，图像计入数据字节。HTTP 头以及链路层封装另有各自开销。可选传输钩子将受控等候和丢失施加在实际发包前或验签前。

| 请求 | 地位 | 成功结果 |
| --- | --- | --- |
| `ISSUE` | 签发或刷新会话许可，绑定端点、会话、代际、有效期、档位、任务数、占用槽位、输入字节及任务预算 | `PERMIT` |
| `SNAPSHOT` | 读取当前槽位、队列和计划服务时延估计 | `SNAPSHOT` |
| `TASK` | 携带已签许可和图像，实际检查当前一并挂载的期限及资源约束 | `RESULT` 或 `OFFER` |
| `SELECT` | 接受指定任务在边缘已缓存输入上生成的降档报价 | `RESULT` |
| `AUDIT` | 读取已签名的开发试验账本统计和分页记录 | `AUDIT` |

## 运行与采用

会话许可授权可选主档 512²、轻量边缘档 384² 和本地 256² 回退，实时执行仍按共享槽位和单任务预算准入。许可还有权威进程启动标识，权限更新时间和到期按权威进程 QPC 判定。相同签发请求的准确重放返回原许可证。新签发更新该会话的有效代际。

终端可在任务上传前依据共同的实测快照选择轻量档。主档已上传时，若主档的估算占用和返回时间超过边缘采用窗口且轻量档可行，`auto` 路径直接转轻量档。配对的 `offer` 路径先返回报价，接受后重用相同已上传数据。两路径共享同一档位、队列、服务估计与实际数据处理。`none` 路径保留选定档位，超时后由终端按本地期限进行安全回退。控制差别发生在是否需要一轮额外的 `OFFER` 后选择；上传、签验与结果返回照常计时。

SQLite 账本对受领方和稳定任务 ID 作唯一执行保护。任务身份一旦写入，即使许可证更新或在同一数据库上重启，重复提交亦不会产生第二个工作认领或结果提交。数据库记录生产者提交的结果摘要。终端应用只采用已验签、载荷摘要匹配、任务相符、符合当前代际和允许档位的结果，最终采用点以严格早于本地边缘截止期和许可证到期为条件。权威端还在执行启动和提交前后检查时刻、代际和资源。迟到的合法应答可以作为日志证据，客户端采用仍拒绝迟到结果。估计不准或链路无响应时，本地回退以及结果丢失均如实记录。

占用、执行认领和结果提交的内部账本统计用于检查实验安全性。结果可用性与截止期界还依赖端点调度、储存、传输时间和本地回退的剩余预算。

## 实验启动

在导入模块的隔离虚拟环境中使用 `write_config()`、`start_server()` 和 `Client.call()`。权威端监听独立的环回端口。端口就绪前使用同一测试图案预热 Pillow 两个服务档位，随后按同一方式启动配对任务。冷会话签发与续签均计入协议运行。Windows 端直接启动基础解释器并使用当前虚拟环境的包目录，试验进程退出后可以释放其数据库和端口。

实验配置中的私钥为一次性夹具，留在本机运行目录。导出的复现证据应包含配置摘要、任务输入摘要、协议时钟、逐任务结果和账本统计。
