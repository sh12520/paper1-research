# Conditional proof / implementation alignment — RDINP-A1-CANDIDATE-2

Status: mathematical derivations and code-alignment review, NOT mechanized whole-program proof. PROVEN below applies only to the stated abstract lemma. Actual Python/SQLite/HTTP paths are TESTED_ONLY; end-to-end timing/storage/authenticity implications are CONDITIONAL. ## Model and assumptions

Two fixed principals, honest single logical authority, authentic fixed-key signatures, non-rolled-back retained database, correct atomic/durable SQLite transactions on the declared storage domain; no side writer/Byzantine corruption. Each authoritative negotiation binds revision/authority/initiator/negotiation/intent/configuration/units. Concurrency is serialized by authority lock and BEGIN IMMEDIATE. Physical resources and cross-authority distributed atomicity are excluded. Each role has a nondecreasing safe-ns boot-bound origin; boot inputs/rates require environmental validation. Same-boot persisted fence prevents only regressions behind saved observations, not arbitrary false boot labels. Client storage does not lose completed write-ahead or receipt records. Permanent crash, media loss, Byzantine signing and arbitrary scheduling delay are outside liveness guarantees.

## S1: logical capacity — PROVEN abstract inductive lemma; implementation CONDITIONAL/TESTED_ONLY

Let U=sum units for RESERVED and CONFIRMED; initially U=0, 0<=Q<=P. At a serialized reservation, require x<=max(0,Q−U), so U'=U+x<=Q<=P. REJECT leaves U. COMMIT transfers RESERVED→CONFIRMED with the same units, so U'=U. Expiry/cleanup/boot invalidation only remove RESERVED, decreasing U. No other transition increases U. Induction gives 0<=U<=P at each transaction boundary. Q can subsequently fall below U without violating P. Exact big-integer comparison avoids overflow in U+x; every persisted unit is safe. This does not prove physical bandwidth/CPU admission.

Mapping: Authority.business initial admission/commit, cleanup, __init__ boot transaction, set_admission. Effects and decisions commit with attempts/transaction records. Tests V7 race/admission shrink/duplicate commit; offline review independently reconstructs every saved journal prefix and final usage. Python/SQLite correctness is assumed, not proven by the finite traces.

## S2: one authoritative outcome and first-effect order — PROVEN abstract transition lemma

Per key, only absent→RESERVED/REJECTED at INTENT_INITIAL; processed INTENT_REPLAY sets prerequisite, never allocates. Only COMMIT_INITIAL with matching decision/token/epoch and prerequisite can first apply; COMMIT_REPLAY cannot apply. Receipt is persistent and immutable thereafter; CONFIRMED never expires; permanent NOT_APPLIED prevents later apply. Historical decision and receipt replay their own stable body. Thus no path produces both COMMITTED and NOT_APPLIED for one key, or two distinct first commits. This is not common knowledge, consensus, or a guarantee after Byzantine/rolled-back storage.

Mapping: business prerequisite/receipt checks precede expiry; register atomically enforces raw/JCS attempt identity and retained global nonce/message IDs; transactions/effects/response body share commit. V3/V4/V5/V7 tests and offline digest/SQL joins support this finite implementation. NEW key after UNKNOWN is not equivalent identity; clients must not retry with a fresh negotiation to infer non-effect.

## K1: unknown vs known effect — PROVEN indistinguishability / CONDITIONAL authenticity

A lost COMMIT request and a committed request whose response is lost produce the same client timeout. Hence timeout cannot establish NOT_APPLIED or authority REJECT. Durable commitPossible before possible COMMIT egress prevents a crash-induced false negative; false positives are safe (write-ahead then crash before send). A properly authenticated, identity/config-bound COMMITTED receipt proves commitment under honest authority/storage assumptions. Confirmation failure does not revoke that proof; RECOVERY_REQUIRED can have COMMITTED knowledge. NOT_APPLIED is usable only from the persistent irreversible receipt, not HTTP errors. Invalid/late responses cannot become winners; valid receipt knowledge incorporated before immutable terminal is preserved independently of winner eligibility; post-terminal late evidence is audit-only, not online outcome closure.

Mapping: Initiator persist before phase 3 schedule; verified receipt knowledge separate from latch; terminal uniqueness under serializer; recover_offline never refreshes timers/keys. Server commit exceptions yield INTERNAL_UNKNOWN, never guessed rollback. Tests response suppression, ambiguous post-commit exception, client exit 23 before egress and exit 24 after first receipt, responder exit 17 after commit, late receipt knowledge. No OS power-loss storage qualification follows from these process exits.

## T1: bilateral bounded loss — PROVEN combinatorial lemma

For Bq consecutive request losses and Br consecutive response losses, K=(Bq+1)(Br+1) sent requests contain at least Br+1 delivered requests (partition into Br+1 groups of Bq+1). Each valid admitted request produces one correlated business response under live bounded processing and egress. At least one of those Br+1 responses survives a response burst <=Br. No application duplication; stream indices scoped to this negotiation/phase/direction. Requests can be processed/replies reordered: count argument still holds and old attempts remain eligible. If per-attempt scheduled send→verified post-store latch upper observation is <=C and R schedules sends, H=(K−1)R+C bounds the useful response. H must be STRICTLY before the effective cutoff. Every valid ingress must reply, including identical replay; a silent dedup or phase problem breaks the premise.

Mapping: attempts>=K in Contract; initiator has no RTO retirement, no redirects/transparent retries; lock-free network/verification, serialized tentative winner with post-store time upper check. Main retry signing/scheduling jitter, responder queue/fsync/signing, client verification/serializer and monitoring costs must be covered in C; unbounded OS pauses are not permitted by this implication. Finite enumeration Bq,Br<=2 checks 11,533 stream pairs (TESTED_ONLY corroboration), plus actual local request sink/response suppression and R<C non-retiring test. This does not prove wireless loss assumptions or derive C from measured maxima.

## T2: full sequence, publication and strict equality — CONDITIONAL

Let I=first_phase_origin−immutable_start, including initial durable state, start trace and first serializer setup; require 0<=I<=I_budget=initialBudgetMs. Let h_i=(K_i−1)R_i+C_i and d_i bound validated latch→next phase origin (including winner persistence/commitPossible). C_i starts at the attempt due, not negotiation start; authenticated receipt persistence and draft validation occur within C_i. Rejection requires I_budget+h0+d0+h1+V_reject < T_reject; success requires I_budget+sum(h_i)+sum(d_i for transitions i=0..2)+V_commit < T_final. V begins at the last validated latch and includes last winner persistence, terminal persistence and queue publication; no additional d_last is counted. For every i, I_budget+sum(h_0..h_i)+sum(d_0..d_(i−1)) < effective_cutoff_i. Contract prefix starts at I_budget. Observed I>I_budget safely refuses BEFORE any send, never sliding start and never counting as successful liveness; I=I_budget can succeed only with strict cumulative slack. Failure trigger F obeys F+J_fail+V_fail+margin < T_final. Permanent initial persistence stalls cannot guarantee publication and violate the execution premise.

Induction: phase 0 origin <=start+I_budget. Each phase latches within h_i of its origin under T1; next origin <=latch+d_i. Thus the cumulative expression bounds every latch and the final V bounds publication. This closes the previously missing initial interval without redefining start or altering RTO/non-retirement. Phase selection uses private draft + strict post-store upper validation; official main-loop winner appears only after successful persistence. ClockError discards draft and sets a sticky controller fault under the same serializer, so good later ticks/competing replies cannot make the failed selection usable. Receipt knowledge is persisted independently, before draft processing. Winner-persist failure restores pre-winner state and stops progress (cleanup storage must still be operative). Process exit before draft validation leaves no draft on disk; after successful validated persistence, only offline recovery is allowed. The observations do not make clock/store/fsync one atomic event.

Publication remains immutable result queue insertion AFTER terminal persistence; post-insertion sample bounds it from above. Trace/caller scheduling after publication is separate. Late publication/clock failure never claims deadline success. All arithmetic is sufficient only under actual I/C/d/V, scheduler, clock and storage bounds; local finite tests do not qualify these bounds.

Mapping: Contract.cutoff_ms + checks; Initiator phase condition serializer/post-store rollback, terminal queue publication, terminal recovery. V8 equality before/after store and publication overrun. No finite running program can guarantee dispatch/publication during arbitrary permanent pause or failed durable storage. Those are explicit failed premises, not protocol rejection or a new clock origin. Client clock failure safely publishes without a fabricated timestamp when storage/scheduler still execute.

## T3: strict lease tail — CONDITIONAL, not universal SQLite WCET proof

At server final check t, guard t+T_tail+epsilon < expiry. If the **entire** remaining transaction tail actual duration <=T_tail, durable completion return observation is <=t+T_tail<expiry. An earlier INSERT/check time alone cannot prove this. The journal/transactions/hash/metadata write/fsync/commit-return sample are all in the tail. If actual tail exceeds declaration or return reaches expiry, a persistent commit may already exist: record premise violation and preserve it, never fabricate NOT_APPLIED/rollback. V6 intentionally retains this counterexample. No finite local stress test proves a hard T_tail; ordinary host/fsync lacks qualified worst-case source here.

Noncircular guardability: conservative client prefix S=I_budget+h0+d0+h1+d1, last necessary COMMIT send S+(K2−1)R2, plus client send jitter/observation error; convert by ceil(serverRateUpper/clientRateLower), add real request-delivery bound converted by server upper rate, server preprocessing/transaction-lock bound and server observation error. This is B_check independent of successful commit. Require lease >B_check+T_tail+epsilon. Otherwise startup rejects contract; increasing attempts/numbers does not repair infeasibility silently. Reservation anchor is causally after negotiation start, making this start-based prefix conservative; no claim that initial delay actually consumes the lease before reservation. Strict-tail semantics/guard remain unchanged. Inputs are declared unqualified fixture values, not real host qualifications. Plan unit conversion is explicit in SIGNING-AND-PREIMAGES.md.

Mapping: Contract.guard_bound, Authority final guard and post-return monitoring. Guard equality/infeasible lease/tail-overrun tests. Liveness additionally needs reserve admission or a stable capacity rejection, and the declared bounded execution assumptions. Safe refusal alone does not establish successful liveness.

## R1: cleanup/restart — CONDITIONAL

Active scheduler dispatch J after expiry and completion X give release<=expiry+J+X, with J+X<=G. Code monitors dispatch, completion and total separately. Only tentative reservations are released. On real boot/origin change, atomically invalidate tentative and increment epoch before admission; confirmed and irreversible receipts survive. Same-boot retained clock fence prevents restart behind saved tick; old live boot instances cannot mutate effects/cleanup after metadata boot changes. Finite process exits/reopen exercise these paths; arbitrary outage, incorrect boot labels, OS/power/media failures remain unqualified. No online recovery procedure is promised.
