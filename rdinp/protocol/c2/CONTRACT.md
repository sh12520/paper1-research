## C1 Configuration and identity

Closed plan/policy/timing schemas are in contracts.schema.json. Both ends recompute all digests before use. A negotiation is scoped by revision, authority, initiator, negotiationId and intentId. One authority database binds each negotiationId permanently to intentId, initiator, units and configuration digest. New identities are NOT a safe retry for unknown effects. Retention is indefinite in this candidate: no pruning, key rotation or implicit database migration.

Plan/policy bytes are independent of timing. SHA256 of raw plan bytes and domain-separated JCS(policy) feed timing; SHA256(domain + JCS(timing)) is timingContractDigest. All integer and derived arithmetic is safe (<=9007199254740991); no floating JSON numbers, duplicate keys or surrogate Unicode. JCS sorts UTF-16 code units. Domains are ASCII revision + ':' + kind + NUL, where kind is POLICY, TIMING, DECISION or RECEIPT. No circular references. Schema IDs are identifiers, never fetched over network.

Requests carry phase and attempt, unique messageId/nonce, fixed timing digest and fixed business body. New attempts use new IDs/nonces. Exact repeated attempt must preserve signed logical JCS AND raw bytes; conflicting attempt identity is a non-authoritative problem with no effects. Static trust pins kid, PEM, principal, role and revision. A known nonce from an identical attempt is legal replay, not silently discarded. Signing authenticates bytes under configured keys, not real-world identity/authorization qualification.

## C2 Four phases and authority

INTENT_INITIAL → INTENT_REPLAY → COMMIT_INITIAL → COMMIT_REPLAY. INTENT phases use INTENT request and DECISION response; COMMIT phases use COMMIT request and RECEIPT response. Rejection terminates after two matching REJECT decisions. Successful completion requires two matching COMMITTED receipts. Receipt contains stable decisionDigest and receiptDigest; full envelope separately correlates request raw/JCS hashes, phase and attempt. A body digest excludes envelope/signature and its own digest field; RECEIPT retains decisionDigest. Stable INTENT business body cannot change to CONFIRMED on replay.

FIRST reservation only by INTENT_INITIAL. INTENT_REPLAY requires an existing decision and never creates/renews a reservation. First COMMIT requires processed INTENT_REPLAY persisted in the same database. COMMIT_REPLAY only reads a prior receipt, never applies a first commit. Stable legal historical requests may be processed out of current phase; this does not prove the initiator received earlier replies. Business-body mismatch, token/epoch mismatch, altered attempt, unauthorized principal and illegal first-effect order fail before effect. All lawful admitted arrivals get one correlated response under live, bounded processing/signing/egress; crashes/response loss are explicit exceptions, not silent dedup semantics.

RESERVED INTENT replay is stable and does not extend lease. EXPIRED INTENT returns signed non-authoritative problem (HTTP 410), never an authoritative REJECT. CONFIRMED or REJECTED retains original historical decision. COMMIT on expired, never-committed reservation may persist stable NOT_APPLIED receipt. NOT_APPLIED then permanently forbids future application under that key. HTTP status/transport failure alone never conveys effect knowledge. Already committed state never expires or reverts.

## C3 SQLite and strict tail

Protected capacity P immutable; admission Q<=P may shrink below existing usage. U=sum(RESERVED+CONFIRMED units). BEGIN IMMEDIATE serializes admissions and all first effects. Reserve only if U+x<=Q; commit changes RESERVED→CONFIRMED without increasing U; expiry releases tentative only. Stable decision/receipt, attempt/raw/nonce identity and effect journal commit atomically. Full synchronous SQLite on an honest, single-owner, non-rolled-back database is assumed. SQL INSERT time is NOT a durability event.

The lease anchor is responder monotonic time during reservation transaction. Before first commit, final check t requires t+tailBudgetNs+tailMarginNs < leaseUntilNs. Tail includes decision/receipt hashing, all SQL, audit/attempt inserts and durable transaction completion. DURABLE_COMMIT_RETURN is measured immediately after SQLite commit returns; if that observation is >= expiry or actual tail exceeds declared budget, record PREMISE_VIOLATION without manufacturing NOT_APPLIED or undoing committed effects. Strict durable-before-expiry is CONDITIONAL on the actual whole tail bound. Ordinary OS/SQLite supplies no demonstrated hard bound here. Commit exceptions are UNKNOWN unless persistent state is safely read back; never infer rollback just from an exception.

Boot label and monotonic origin are explicit deployment inputs, not authenticated by configuration hashes. Both local clocks must be nondecreasing, boot-bound and safe-integer ns. Changed boot atomically expires tentative state before admission, advances epoch, preserves CONFIRMED/REJECTED/receipts. Same-boot restart retains leases and histories. Active cleanup runs even with no requests; only RESERVED→EXPIRED. Conditional release bound is dispatch J + completion X <= cleanup budget G; arbitrary outage/pause cannot meet it. Clock regression stops effects and enters fail-closed handling; no resetting deadlines. Non-Byzantine key/database/clock and no side writer are assumptions.

## C4 Initiator retry, latch, deadlines and knowledge

Persist immutable identity, plan deadlines and state before sending. Persist commitPossible=true BEFORE possible first COMMIT egress. No automatic negotiation restart after process restart: recover persisted terminal, or publish RECOVERY_REQUIRED/UNKNOWN with previous evidence, never refresh deadline. RTO schedules next bounded attempt and does not retire prior attempts. No transparent HTTP retry/redirect. Each planned attempt sent at most once. Worker responses are verified outside the winner serializer; inside it resample monotonic and atomically choose at most one winner strictly before effective phase cutoff. RECEIVE, VERIFY_DONE and PHASE_WINNER_LATCH are distinct events. A timely receive/verify does not make late latch legal. Late replies remain evidence but cannot change terminal or selected winners.

Absolute per-phase cutoffs are measured from immutable negotiation start, never slid. Failure trigger reserves failure dispatch/persistence/publication budgets before final deadline. Rejection success has its own final budget, commitment success its own. TERMINAL_PERSISTED precedes TERMINAL_PUBLISHED. Deadline equality fails closed; when actual publication is late, report PREMISE_VIOLATION, never claim timely termination. Without bounded scheduler/storage costs only eventual stopping upon resumed dispatch is supported.

The provisional response selection is a private draft, not self.winners and not the shared/persistent state. Post-store upper sampling must succeed strictly before cutoff. ClockError discards the draft and sets a sticky controller fault under the serializer; later good ticks or competing replies cannot resume negotiation. Authenticated receipt knowledge is durably retained separately before draft selection. After a valid upper sample, winner state is persisted before the main loop may consume it. Persist exceptions restore pre-winner state and stop the controller; if the storage domain cannot perform cleanup/persistence, no completion/durability guarantee is asserted. A crash before draft validation cannot leave a persisted draft; crash after validated persistence uses existing offline recovery only.

Effect knowledge is separate from protocol confirmation: before possible COMMIT, NO_COMMIT_SENT; after send without authoritative receipt, UNKNOWN; first valid success receipt gives COMMITTED even if second confirmation fails (RECOVERY_REQUIRED with COMMITTED knowledge); valid permanent receipt gives NOT_APPLIED. Conflicting authenticated authority evidence is quarantined, not resolved by choosing a convenient reply. Timeout/problem does not undo knowledge. No online recovery extension: offline inspection of retained receipts/database is allowed.

## C5 Sufficient conditions and accounting

For phase i, K=(Bq+1)(Br+1), H=(K-1)R+C; declared attempts>=K. C covers scheduled send jitter, request delivery, server validation/queue/transaction/sign, response delivery, client verification and latch. Old attempts remain eligible. With bounded directional consecutive loss on this phase's admitted request/response streams, no application duplication, live bounded endpoints and valid business admission, one useful response latches by H. This is a conditional lemma, not a qualified observed maximum. 2*sum(attempts) counts logical endpoint requests+responses, not TCP packets/retransmissions/control traffic.

Cumulative H and transition budgets must strictly precede cutoffs; success publication reserve and failure dispatch/publication reserve must fit final deadlines. Lease guardability is checked without assuming successful commit: prefix before first COMMIT + last required scheduled send, conservatively converted by serverRateUpperPpm/clientRateLowerPpm, plus request-delivery and server-precheck bounds and observation error, plus tail+margin, must be strictly below lease. If these conditions are arithmetically infeasible reject configuration; never enlarge parameters silently. Rate/delivery/precheck/tail assertions need B evidence, not supplied by this A implementation.

Initial cost I is client-clock duration from immutable startNs (before initial state construction/persistence) to the first phase_start sample, INITIAL_READY.observedNs. It includes initial durable state, the NEGOTIATION_START trace and acquiring/setting the first phase serializer state. plan.initialBudgetMs bounds I. Observed I<=budget is admitted; I>budget refuses before any SEND_ACTUAL, with ASSUMPTION_FAILURE/NO_COMMIT_SENT and a premise violation. Equality here is allowed only because all cumulative phase/deadline feasibility inequalities remain strict. Cutoff equality never becomes legal.

Prefix feasibility begins at I_budget, not zero: phase i requires I_budget+sum(H_0..H_i)+sum(d_0..d_(i-1)) < effective_cutoff_i. d_i is successful latch-to-next-phase-origin (includes winner persistence and commitPossible where applicable). C_i covers each due-to-validated-upper path, including request construction, signing/schedule jitter, receipt-knowledge persistence and private draft processing; it does NOT cover initial I or post-latch d_i. Final V covers last latch-to-terminal persistence/queue publication including last winner persistence, not an extra d_last counted twice. Rejection and success add I_budget to their complete sequence inequalities. Conservative start-based lease feasibility also includes I_budget; the strict-tail check/effect semantics themselves are unchanged. Safe initial refusal is not successful liveness. All original fixture cutoff/deadline/R/C/lease/tail numbers are unchanged; new I_budget=100 ms is an unqualified local mechanism input, not measured WCET.
