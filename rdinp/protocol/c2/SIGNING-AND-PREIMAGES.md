# Exact binding, state and event supplement — RDINP-A1-CANDIDATE-2

This is part of the candidate contract, not a new semantic approval or release.

JCS: scalar Unicode strings, UTF-16 code-unit property order, lowercase JSON literals, integers only within ±(2^53−1), no duplicate keys/floats/nonfinite/lone surrogates; no normalization. Wire schema numbers are nonnegative. Protected header and all full-message unsigned payloads use this canonicalization. Both raw wire SHA and full signed logical JCS SHA are retained independently.

Detached compact JWS value = base64url(JCS(header)) + '..' + base64url(r32||s32). Signing input is protected64 + '.' + base64url(JCS(full message minus signature)). Base64url is unpadded and canonical; public key must be P-256, alg ES256. Header **exactly**:

```json
{"alg":"ES256","crit":["rdinp_canon","rdinp_nonce","rdinp_scope"],"kid":"<pinned kid>","rdinp_canon":"JCS-INTEGER-SCALAR-UNICODE","rdinp_nonce":"<message nonce>","rdinp_scope":"RDINP-A1-CANDIDATE-2","typ":"application/rdinp+jws"}
```

Signature envelope is exactly {kid,value}; field algorithm/profile are fixed by revision and protected header. There is no freshness inferred from wall time, caller-supplied public key, remote key fetch or hot rotation. Trust contains exactly two distinct principals, one initiator and one responder. Authorization is static and nonproduction. PEM pins and trust digest are provenance, not a PKI qualification claim.

For POLICY/TIMING use exact closed schema objects. For DECISION/RECEIPT, digest preimage object is exactly {revision,negotiationId,intentId,initiator,authority,timingContractDigest,body}. Initiator/authority come from original request sender/recipient. DECISION body omits both decisionDigest and receiptDigest; RECEIPT omits receiptDigest only, retaining decisionDigest. Domain is ASCII('RDINP-A1-CANDIDATE-2:'+kind) || NUL; digest is lowercase SHA256(domain || JCS(preimage)). Decision identity therefore cannot be transplanted between negotiations, authorities or contracts. A receipt retains exact decisionId/units/epoch/token/leaseUntilNs/decisionDigest; only status, reason and receiptDigest differ. Reply envelope additionally binds full request raw/JCS hashes, phase and attempt. signature/messageId/nonce are fresh per response, while authoritative business body remains stable.

State mapping: INTENT_INITIAL proposes units and atomically produces RESERVED or REJECTED. INTENT_REPLAY persists intent_replayed=1 (the server's logical prepared guard), without changing decision/lease. This means processed prerequisite, not proof of client receipt. COMMIT_INITIAL can change RESERVED→CONFIRMED, or EXPIRED→permanent NOT_APPLIED receipt. COMMIT_REPLAY confirms only an existing receipt. The authority may commit after a client's local timeout but before its own lease cutoff: it cannot observe the client's local origin/deadline. Thus client failure is not a remote abort, and UNKNOWN is necessary. No new reject/abort wire messages or online recovery are added.

Trace `ordinal` is **record append order** within one role's trace, not a global event-order oracle. `ns` is the observation at trace recording under its mutex; `observedNs` (when provided) is an earlier separately sampled event boundary (latch, final check, commit return, queue publication etc.). A concurrent record can be appended later than another event's sample. Latch timing checks use observedNs, not record ns. Causal request/response hashes and serialized per-phase selection establish dependencies; never subtract the two role clocks. Null clock sample/error means unusable timing evidence, not a fabricated tick. TIMEOUT_DUE stores actual observation plus dueNs; it is not backdated to the planned cutoff.

Latch selection is stored in a **private draft** under the operation serializer, never in official winners or persistent state before validation. Post-store upper sample >=cutoff discards it; a sampling ClockError also discards it and durably marks a sticky controller fault, not an ordinary REQUEST_FAILED retry. Only a strict upper sample followed by successful winner persistence permits main-loop consumption. PHASE_WINNER_LATCH marks the validated selection; PHASE_WINNER_PERSISTED is separate. A persistence exception restores pre-winner state and stops progress; storage failures that prevent cleanup remain outside retained-storage guarantees. Valid authenticated receipt knowledge is persisted before the draft, preserved through discard/failure, and late evidence after an immutable terminal is audit-only. No provisional state can be revived by another worker after controller fault. This does not pretend sampling/store/durability is one hardware event.

INITIAL_READY.observedNs is the first phase origin; initialElapsedNs=observedNs-startNs. initialBudgetNs is plan.initialBudgetMs converted to client ns. Start is never resampled on overrun; absence of any first send plus ASSUMPTION_FAILURE is safe refusal, not successful liveness. Initial cost ends at this phase origin; trace/remaining setup afterwards belongs to due-to-latch C, transitions d begin only after successful latch, and final V ends at queue publication. A corrected conditional inequality must account for all these disjoint intervals.

Client publication is insertion of its immutable terminal result into `Initiator.publications`, a local thread-safe queue observable independently of the negotiating thread. `observedNs` on TERMINAL_PUBLISHED is sampled after insertion returns and is a conservative upper observation of that publication point; trace I/O and convenience run() return can occur later. Terminal persistence precedes insertion. Caller/consumer scheduling is not part of the local publication promise. Late publication records a premise violation; no deadline claim is inferred from the presence of the event. Restart with persisted terminal returns the saved result but does not invent an old publication timestamp.

SQLite last_ns is a persisted lower clock fence, not authentication of a boot/origin. Old live instances whose boot differs from database metadata cannot mutate effects/cleanup. Same-boot startup cannot regress behind this persisted fence. The tiny post-last-sample interval cannot authenticate a broken clock on restart; nondecreasing boot/origin remains an explicit environmental assumption. Processes must have one authority ownership domain; no side writers, DB rollback, adversarial storage or Byzantine authority. Process crash is covered by retained SQLite transactions under declared storage assumptions; OS crash/power-loss/media corruption are NOT qualified by local restart tests.

Each admitted HTTP arrival has an independent arrivalId (identical attempt retransmission still has a new arrival). The same SQL transaction stores request raw/JCS hashes, kind/body and transactionId; effect journal rows reference that transactionId. DURABLE_COMMIT_RETURN records its post-return upper sample and arrivalId. RESPONSE_EGRESS associates the signed response with arrivalId and request hash. Boot/cleanup effects have independent transactionIds and explicit BOOT_READY/RELEASE_DONE observations, not fake request arrivals. SQL sample_ns is a pre-durability sample only. Cleanup independently monitors dispatch J, completion X and total G premise violations.

Plan units: retry/clean/cutoff/transition/deadline are client-clock milliseconds; lease/tail are server-clock nanoseconds; requestDeliveryNs is a real-duration bound converted with serverRateUpperPpm, serverPrecheckNs is server-clock duration, sendJitterNs is client-clock duration. Cleanup J/X/G are server-clock milliseconds (the OS timer mechanism is not thereby qualified). Rate fields express local clock units per million real units; exact integer ceilings are used. Values bind declared conditions, never certify them.
