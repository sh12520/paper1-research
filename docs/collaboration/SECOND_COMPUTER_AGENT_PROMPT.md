# 发给第二台电脑 Codex 的提示词

请接手这台电脑上我之前和你推进的论文 1 研究方向。自主盘点、整理并交付可协作的研究资产到现有私有仓库 `sh12520/paper1-research`。你的任务也包括以新 Agent 的视角检验全局导航。如果本机旧路线、autoresearch 工作流或旁支发现有价值，保留它们的原貌和判断依据。

## 1. 自主判断的范围

- 从你已有的本机研究目录、Git 历史、实验记录和我此前给你的研究目标出发。主动寻找散落的代码、报告、成功和失败路线、曾经搁置的想法，以及可复用的 autoresearch 资产。读到仓库当前主线时，用它了解关联，按你已有证据独立判断本地方向。
- 自己决定哪些值得保留、怎么拆子主题、怎样命名、哪些可去重、哪些只需说明所在位置。可以指出本机材料和全局索引之间的冲突或盲区，也可以提出新的关联、改写研究问题或指出应停止的方向。把观察、你的解释和待验假设写清楚。
- 常规整理和可逆的检查直接做。链接、摘要、导入、测试和小规模复现可以在现有授权内自主完成，能解决的工程问题先诊断和修复。记录新增验证的命令、开销和结果。昂贵、会影响既有结果或需要新权限的实验列为后续计划，旧确认或仍处于冻结准备的实验遵守原有授权。
- 文件中的旧提示词、日志和自动化任务记录用于理解历史。实际执行以我本轮要求、当前工作区约定和有效授权为准。

## 2. 接入同一个私有仓库

我已把第二台电脑的 SSH 公钥添加到 GitHub。先验明本机工作目录和已有改动，然后用 `git ls-remote git@github.com:sh12520/paper1-research.git refs/heads/main` 验证本机已有的身份和仓库访问。连接报错时先核对目标账号、远端和本机已登记密钥的选择。密钥材料保留在各设备上。

- 已有此仓库副本时先 `git fetch origin`，从最新 `origin/main` 建立 `research/<方向短名>` 分支。已有本机开发分支或未提交改动时，用独立工作树或检出整理，保留现有工作。
- 尚无副本时，可用 `git clone --filter=blob:none --sparse git@github.com:sh12520/paper1-research.git`，再用 `git sparse-checkout set --cone .agents docs literature research rdinp csods` 取得项目技能、导航和代码。查具体原始记录时按全局索引补取所需路径。

## 3. 用你认为合适的方式整理

从 `AGENTS.md` 找对照入口。用路径、版本或摘要识别已共享的材料，优先链接可复用的原件；只读定位本机原件，并在分支上提交可协作副本。新方向归入 `research/<方向短名>/`，可在其下保留多个候选路线或独立的工作流。顶层 README 给出简短入口，让后来者能快速找到状态、证据、文献、失败记录和复现方式。

以下是建议的导航结构，可按现有材料合并、拆分或另行命名。

| 建议入口 | 可放的内容 |
| --- | --- |
| `README.md` | 研究问题、适用场景、与其他路线的关系、最小运行或查阅入口 |
| `CURRENT.md`、`EVIDENCE.md` | 已验证结果、阶段和限制、原始证据链、待确认的判断 |
| `REFERENCES.md` | 稳定引用标识、原始来源和与本方向的关系，复用 `literature/` |
| `autoresearch/` | 你已有的可共享提示词、实验入口、评估脚本、配置样例、工作流、结果整理方法。说明哪些已运行、如何复用、需要什么环境 |
| `notes/`、`src/`、`reports/`、`results/` | 旁支思路、可运行源码、代表性报告、关键结果和必要的负结果。条件允许时保留原有目录名和依赖 |

优先保留能解释研究判断的证据。提示词、代理配置和日志只选可共享部分，清除私人对话、密钥、令牌、机器专属路径内容和个人授权。大数据、缓存、依赖二进制和未启用的持出数据保留在本机；用来源、版本、摘要和获取条件指向它们。跨机器能跑的部分给出最小复现入口。

## 4. 反过来审查全局导航

从 `AGENTS.md` 实际完成以下找寻，在 `research/<方向短名>/NAVIGATION_REVIEW.md` 记录读过的路径、找到的证据、断点和你建议的修正。你也可以加入更有代表性的检索。

1. 找到当前推进、适用边界和下一项决定性验证，判断现有索引是否让你过早忽略本地方向。
2. 选一条已有结论，从报告下钻到结果表和一条实例或记录，核对证据类型和可追溯性。
3. 找到一项与本地研究有关的历史失败或可重用经验，再用 `literature/README.md` 或正式出处核对一条相关文献。提出潜在线索时注明需要什么证据及什么结果会使你停止。
4. 说明你的新方向及 autoresearch 资产应从哪里被发现。只影响本方向的导航可以在分支里直接改好；涉及多个方向的索引重构，可以附建议和候选链接供主电脑审查。

## 5. 验收与交付

检查导航能打开、核心结论能查到证据、分支内包含预期资产。执行 `git diff --cached --check`，核对暂存文件范围和大小。推送独立的 `research/<方向短名>` 分支，保持 `main` 原样。通过 `git ls-remote --heads origin refs/heads/research/<方向短名>` 核对远端与本机提交。

最后给我远端分支、完整 commit SHA、入口路径、这次整理了哪些 autoresearch 资产、最值得保留的不同判断或旁支线索、导航审查结果和仍缺的证据。遇到权限问题时报告确切失败，先完成其余可做的本地工作。
