# Research map

## RDINP

RDINP studies conditional bilateral resource commitment under message faults and deadlines. The reference controller gives an authoritative logical resource result and a separate client view. A lost response can leave the client with UNKNOWN while the authority has already committed.

Local execution diagnostics distinguish control acknowledgement, a valid execution slot, a workload result and timely application adoption. The sequence of prototype checks covers one task, sequential reuse, durable recovery, stale writes and a software reverse-proxy actuator. Status queries, leases, supervision, epoch checks and deadline guards are baseline techniques. The local experiments describe controlled faults and software execution. Field wireless guarantees and independent superiority remain open.

## CS-ODS

The earlier method line studies exact on-demand enumeration of ranked structured communication-intent contracts in a finite capability-constrained DSL. The export contains the source relevant to that search and small checks. Original research source and completed development evidence are in the [GENSPACE archive](../archive/genspace/). Reduced-domain checks support the bounded implementation scope and do not replace the original development or independent evaluation.

## OPV2V development evidence

The [OPV2V archive](../archive/v2x-development/) preserves communication and compute sensitivity results, paired task records and queue-diagnostic timelines. The November Ubuntu runtime and original dataset remain external dependencies. The concurrent experiment recorded as blocked in the diagnostic report still requires the original workload.

## Relationship

RDINP concerns whether a commitment and subsequent execution can be justified at a deadline. CS-ODS concerns how candidate contract structures can be generated and ordered. Each subproject has its own inputs, assumptions and claims.
