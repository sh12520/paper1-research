# 面向6G智能体网络的限时意图协商与服务履约保障机制研究

**硕士学位论文开题报告初稿**

本稿保留开题阶段的研究方案。2026-11-28 G1-A 的实际运行及后续门禁见[当前推进](../current-research.md)。

对应导师课题《面向6G智能体网络的意图协商协议与机制设计》。

## 一、选题依据

### （一）研究背景与意义

边缘推理、业务代理和环境感知等服务要求终端在业务截止前拿到可用结果。以端边图像处理为例，终端可以在本地生成较低分辨率的结果，也可以请求边缘执行质量更高的处理。终端知道可接受的质量、结果采用期限和本地处理所需时间，边缘掌握当前准入条件、执行队列及结果发布状态。提交请求和回执经由不可靠链路交换，通信、排队、计算和读回都消耗同一任务的时间预算。终端等待过久会压缩本地回退时间，过早放弃也可能损失仍能按期交付的边缘结果。多个终端共享边缘算力时，已回退任务继续占用执行槽，还可能影响后继任务。

值得检验的矛盾产生于双方对同一任务所知不同。终端未收到提交回执时，边缘可能还没有收到请求，也可能已经完成提交甚至启动执行。此时终端应根据自身时限决定是否回退，边缘则需根据实际执行进度判断是否可以停止任务和归还资源。对这类故障，协议承诺、执行许可、实际占槽、结果可读及终端采用分别对应不同的事件。单看协商成功率或平均时延，无法判断哪些任务错过业务期限、哪些结果质量不足，以及哪些资源仍被已回退任务占用。

本课题以具有独立截止期的终端—边缘任务为应用单位，研究可表示的资源约束、具备条件的期限保障以及故障后行为的一致性。科学意义在于识别完成时限、执行安全和资源复用之间何时发生约束冲突，并通过可证伪的对照限定问题的成立范围。工程意义在于形成可复核的协议、接口和执行记录，使业务方能够把提交不确定、结果过期、重复计算和槽位长时间占用分别归因。面向6G是应用和体系背景，首轮实证采用边缘算力及可控链路，实际结论限定于已验证的执行状态和链路条件。

### （二）国内外研究现状

**标准规范。** 3GPP TS 22.186 Rel-19 V19.0.0 §5.4 给出扩展传感场景的通信载荷、时延与可靠性要求，§5.5 规定远程驾驶信息交换的指标。表 5.5-1 中的 5 ms 对应特定通信交换场景。TS 22.261 V19.13.0 §3.1 给出通信服务可用性等术语，§7.2.1 区分空口、系统传输、服务器侧传输和数据处理所占的时间。本文据此分别预算通信段与任务处理段，整个任务的结果采用期限由目标业务给出。TS 28.312 Rel-20 V20.1.0 §5.3.1 涉及意图处理能力查询，§5.3.9.3 涉及在保持其他目标规定范围的条件下查询最佳可达结果，§6.2.2.1.2 描述边缘服务支持期望。其管理服务语义为意图、能力、期望和履约反馈提供定义参考。本文考察单个任务的提交、执行和按期采用，并以实际执行证据解释满足与否。[1–3]

**意图协商和限时事务。** Sharma 等提出意图驱动服务管理的协商框架，讨论在服务提供方资源约束下通过协商和备选意图提高接受机会，为候选意图、可行性判断及接受过程提供直接比较对象。Davidson、Lee 和 Wolfe 提出的 Timed Atomic Commitment 已同时讨论决策期限、动作期限、资源预留及故障条件下的异常状态。Sharma 等的框架用于比较备选意图生成和接受过程。Timed Atomic Commitment 用于核对限时决定及动作的条件语义。本文据此进一步区分承诺成立与业务结果按期采用，并把承诺后的排队、执行与资源复用纳入评价。[4–5]

**分布式执行与协议先例。** Burrows 的 Chubby §2.4 使用由接收方核验的序列凭证约束旧持有者的请求，为执行点识别旧代际提供先例。Lee 等的 RIFL 将请求身份、完成记录和重试接入已有操作，说明在回复丢失后使用持久结果处理重复调用的可行思路。RFC 8480 §3.4.4–§3.4.6 规定 6TiSCH 6P 事务的超时、终止、序号管理与不一致检测，服务对象是 TSCH 相邻节点的资源调度。RFC 7252 的消息可靠性与条件请求支持重复处理控制及资源修改条件，其中 §5.10.8.1 的 If-Match 对执行接口设计有参考意义。RFC 6241 §8.4 的 confirmed commit 提供配置确认和超时回滚语义。据此将持久结果重查、幂等重试、有限租约、执行点代际检查及期限守卫纳入强基线。待验证的差异集中在启用这些机制之后，接收回退事实的时机是否仍影响其他任务的合格交付。[6–10]

**应用系统研究。** Where2comm 以空间置信信息引导选择性共享。How2comm 关注通信特征选择和时空协作融合。BlindMap 的 INFOCOM 2026 会版以盲区预测支持免逐帧请求的感知交换。OPV2V 提供仿真多车辆感知数据与融合评测入口。这些工作表明，任务设定应同时交代通信载荷、处理时延和结果质量。协同感知文献评估信息选择与融合，本课题从服务交付角度考察计算与通信约束下的结果采用及失败处置。[11–14]

**国内研究。** 杨静雅等在《通信学报》讨论意图抽象和知识联合驱动的6G内生智能网络架构，关注从用户期望转向可实施的网络配置。段晓东等在《通信学报》研究智能体通信网络体系与原型，为面向智能体的通信服务提供架构背景。周伟杰等《意图驱动的智能体通感算控一体化融合网络：架构、协议设计与实现》发表于《中国科学：信息科学》2026 年第 56 卷第 11 期，页码 2843–2859，出版信息已由期刊目录核对。全文技术细节待进一步核对，当前仅据出版信息将其列为优先对照文献。[15–17]

### （三）现状评述与选题落点

相关工作分别提供需求表达、备选协商、可靠事务、条件写入、资源预留与边缘任务优化的方法。本课题采用三层证据口径。标准原文用于核对术语和能力边界，论文报告用于理解机制和适用场景，本项目已复现结果仅根据运行产物及审校路径确认。在此基础上，本课题的研究问题是，边缘与终端因通信故障暂时掌握不同状态时，采用状态查询、持久结果、租约和执行点守卫后，是否仍有任务因回退信息迟滞而错过合格交付。这个问题连接了资源条款、时间保障和故障恢复。资源条款决定任务能否准入，期限决定何时可以继续等待或必须回退，故障恢复决定旧执行何时结束和资源何时可复用。拟通过同任务对照分离信息迟滞与停止执行的代价，再判断改善是否需要修改协商行为。

## 二、研究内容和目标

### （一）核心科学问题及研究对象

本课题研究不可靠链路下，端边智能体如何用资源条款约束准入和执行，并在规定期限内交付合格结果或触发安全回退。三个子问题分别对应资源表达、限时决策和故障恢复。资源表达经资格校验后，可形成受时间和作用域约束的执行许可。限时决策以许可、业务截止和已知任务状态为依据，输出继续等待、采用结果或启动回退的决定。故障恢复检查这些决定是否已经在两端生效，以及旧任务释放资源的时刻有无影响新任务的准入和交付。三部分由同一任务身份贯通，最终以实际结果及资源状态验证。

基本单元为终端智能体发起的单个任务 $j$。终端给出输入、可接受质量、相对截止预算 $D_j$ 和本地回退能力，边缘报告能力、安排执行槽位并负责发布结果。每个任务的终端和边缘构成一对协商主体。多个终端可以同时与同一边缘协商，共享有限数量的实际执行槽。预研中的权威承诺由一个持久账本记录。并发扩展仍围绕同一边缘资源管理者进行。终端状态记录其何时得知结果与何时回退，权威账本记录承诺是否持久化，执行点记录代际、实际占用及业务结果。相同的终端超时状态可以对应不同的账本事实。相同的持久承诺也可以对应未开始、正在执行或已经释放槽位等不同执行状态。

以任务释放时刻 $a_j$ 为起点，业务结果采用的截止为 $d_j=a_j+D_j$。本地回退预算记为 $B_{\mathrm{local},j}$，包括输入准备、处理、校验与采用。固定回退策略在 $f_j=d_j-B_{\mathrm{local},j}$ 检查是否已有可采用的合格结果。若没有，终端按既定策略启动本地处理。若 $B_{\mathrm{local},j}>D_j$，则在任务释放时标记该档位的回退预算不足，并保留该任务参与交付统计。回退启动后的迟到回复可以用于澄清远端状态，边缘结果是否仍可采用由预先确定的业务规则决定。研究将分别记录远端承诺是否成立、回退是否启动、远端结果是否被采用和最终交付是否满足最低质量。向边缘发送取消以及安全停止已有执行，是与终端回退决定相关但可单独观察的事件。

### （二）子问题一　资源约束怎样进入协商消息

以导师指定的 A2A、ACP、ADP 对照框架审查消息类型、Schema 和签名边界，沿用 RDINP 已实现的版本与签名结构核对任务身份、请求有效期、资源需求、承诺和结果条款。资源段应区分需求、可用能力、预留承诺以及实际使用。终端的需求表达至少要含资源类型、资源度量和单位、数量、适用作用域、有效时段、最低可接受档位以及缺省处理方式。算力部分首轮以执行槽数、占用时间或可观察的服务时间预算为主。频谱部分在协议接口和 JSON Schema 中表达资源类型、频带或带宽单位、容量与适用时段，并规定来源、权限和字段兼容规则。Schema 校验负责检查字段与单位，准入还需核对实际能力、作用域和有效时段。端点收到语法正确、当前无法执行的约束时，应按规范返回不支持或拒绝原因。首轮实证采用算力执行槽，核对资源从请求、承诺到实占与可复用的过程。频谱分配需要额外接入有授权的控制接口。

每次协商用全局唯一的任务标识、输入摘要、消息版本、参与方身份和相应签名绑定同一份约束。接受或拒绝应明确以哪个版本的资源视图和条款为准，并保留可解释的拒绝原因。在允许重试的环节，同一任务、同一输入、同一版本的重复消息应用已声明的幂等语义。对相同任务标识但输入摘要或请求目的不同的操作，应明确拒绝冲突或经授权创建新任务。重新准入涉及的新执行代际由资源权威端授予，并与旧代际区分。签名绑定请求和承诺的内容，实际许可条件由掌握资源和时钟状态的执行点再次核对。

预期完成一份面向任务的协议消息与接口规范，配套 JSON Schema、状态迁移表、字段约束和正反例测试。验证覆盖有效报价、资源超限、版本不兼容、失效授权、重复提交、改变输入的重放以及未支持资源字段。关键检验是表达出来的约束是否确能约束准入和执行，并在见证失败时指出具体字段、能力或时段。该项以可运行的算力接口和可追溯的检查结果作为验收依据。

### （三）子问题二　怎样在协商、执行和回退中保证时间敏感性

拟从通信、执行准备和业务结果采用三个层级分配时间预算。通信层包括请求、提交回执、状态查询及结果传送。执行层包括排队、资源许可检查、计算、结果持久化以及可见性验证。终端层包括读回、摘要核验、质量判断、本地回退和最终采用。计划在现有四阶段协议之外明确业务激活截止、许可有效范围及结果采用截止的作用。对每个计时判断明确使用哪一端的时钟和哪一种事件。

执行点最后一次检查与业务动作实际生效之间仍有处理尾段。设 $t_{\mathrm{edge}}$ 为边缘单调时钟记录的检查时刻，$T_{\mathrm{tail}}$ 为从该检查到指定执行效果可见的保守耗时上界，$\hat d_{\mathrm{effect},j}$ 为换算到该时钟域的执行生效截止，$\epsilon_j$ 为换算误差的保守上界，且各量使用同一时间单位。拟在这些边界可建立时核查如下充分条件。

$$t_{\mathrm{edge}}+T_{\mathrm{tail}}+\epsilon_j<\hat d_{\mathrm{effect},j}$$

执行生效期限应为结果传送、终端核验及采用留出时间。上式只约束指定执行效果，任务是否按期交付由终端同一时钟域内的实际采用记录和目标 SLA 判定。C2 原有严格时限守卫约束其对应的持久提交，扩展至业务效果时需重新核对完整执行尾段。跨主机事件按任务身份和消息因果关系关联。有限次数测得的最大耗时只能描述试验条件。缺少可证明的尾段界或时钟误差界时，只报告观测时延、异常和回退结果。[E7]

预期建立期限预算与业务状态对照表，形成发起方检查、执行点检查和终端采用检查的记录规则。依次核对准时通过、迟到拒绝、仅有管理回执、实际结果尚未可读、过期结果到达以及回退完成。计划在同一任务和质量口径下核对按期边缘采用与按期回退。结果质量和采用终点固定时，才比较不同机制的时间成本和收益。

### （四）子问题三　怎样在动态智能体与共享执行条件下维持可靠性

首轮动态性主要来自终端任务陆续释放、通信阶段失联、执行者重启、旧请求在途以及一个任务的占用影响后续准入。已有权威记录用于区分尚未提交、已承诺、已取得执行资格、执行中、结果持久化与任务结束。执行点需要区分未用许可到期、运行中的请求停止、已可复用槽位以及对外副作用已出现。对尚未启动的执行许可，可以检查有限租约到期能否阻止旧许可再次使用。对运行中的任务，先验证旧执行是否安全停止，并由结果写入点检查代际与副作用条件。只有实际占用结束，才将槽位记为可复用。重启后按任务身份查询有效许可和持久结果，重复提交须遵守该状态和代际限制。若执行结果已对外可见，照常保留该效果的历史记录。

终端可根据自身采用期限和本地处理能力作出回退。边缘则能判断旧任务是否仍在运行、当前代际是否有效以及执行槽能否让给其他任务。研究将检验在双方采用状态查询、有限租约、常规监督回收和因果取消后，哪类事实仍只由一方及时掌握，是否造成可归因的准入或交付损失。动态智能体发现作为后续可选扩展，第一阶段使用预先配置身份和明确的认证关系，先把任务状态与执行可靠性做实。

可靠性目标包括任务状态可追溯、同一操作重试不会生成重复业务效果、旧代或超期结果的处置有据可查，以及安全释槽。重复计算耗费的执行时间与重复业务效果分别记录。对故障导致的信息缺口应在输出中保留其状态与原因。对可确定的异常和可重复的恢复行为建立固定的正反例。对无法安全停止的任务，记录其继续占用多久、是否影响后续请求以及是否已产生不可回滚效果。

### （五）关键假设与预期目标

- **假设一，提交观测分歧在特定任务下会形成业务残差。** 在状态重查、有限租约、执行点守卫和因果取消均启用时，若回退后仍占用可安全释放的执行槽，且后继任务的剩余时间不足以等待，可能出现可归因的合格结果超期或降档。反例包括本地结果已普遍满足业务要求、预先公布的回退界限已缩短无用占用，以及无排队需求可利用更早释放。观测到这些反例时应收窄或结束该假设。
- **假设二，信息延迟与安全停止成本可分别解释观察差距。** 给边缘瞬时回退信息后，沿用同一取消与执行安全机制仍可能让其他任务提前取得资源。若改善只在把停止代价也设为零时出现，得到的是执行撤销代价方面的线索。该结果将约束哪类协议改动具有现实价值。
- **假设三，受限条件下的执行规则可以在不引入额外违规的前提下改善至少一项业务指标。** 前提是先获得真实或明确标注的可复现开发负载上的残差，再选择具备可执行动作的最小机制。主要检验合格结果按期采用、回退率、过期或重复副作用、无效占槽和额外协议开销。若额外通知无法早于普通取消抵达，或新增轮次反而压缩可用执行时间，预期收益将受到限制。

阶段成果包括协议接口、端边运行原型和同任务配对实验。协议接口以有效承诺、资源超限和旧代拒绝等正反例验收。并发原型须能用一个任务标识关联提交、准入、执行、读回、回退或采用和释槽。配对实验须能区分回退信息迟滞、运行中停止代价及缺少后继请求等情形。小论文以其中能够复现的业务机制及边界为论证对象，硕士论文围绕同一问题补足协议语义、条件性期限论证和跨链路复测。

## 三、研究方案及可行性分析

### （一）技术路线与任务模型

以既有 RDINP C2 状态机和持久执行原型为起点，先补足任务状态、业务读回和物理槽位的关联，再实现可重放的并发对照。初步采用能核对输入与输出摘要的 CPU 图像处理任务构建端到端流程。边缘执行较高质量档，终端提供低档回退。原顺序任务已测过本地处理和回退，新增并发条件下的预算须重新计量。质量按事前固定的分辨率或其他有效业务指标判断，输出摘要用于核对结果关联与完整性。比较前确定最低质量、首次可读的定义及采用期限。该载荷用于验证时序、并发和安全行为。具体应用的 SLA 仍待结合业务方意见确定。收集到可用业务轨迹后，按同一接口替换载荷并重新核验服务时间分布和质量条件。

在一次运行中以 4 个或 8 个终端进程共享 1 个或 2 个物理执行槽。基于无注入条件下测得的单任务服务时间 $S$，用 $\rho=\lambda\,\mathbb E[S]/m$ 定义标称负载，其中 $\lambda$ 为总任务释放率、$m$ 为并行槽位数。扫描 0.4、0.7、0.9 三个负载档，并记录实际排队长度、占用率和有效服务时间。分别设置正常、上行受扰、下行受扰和双向受扰条件，覆盖故障开始与回退时刻相邻的情形。租约长度、重查间隔和本地预算在比较前根据无故障测量及业务允许范围确定。允许 B1 使用公开的回退时刻及业务采用规则。如果边缘依据保守时钟界和结果发布状态已可判定该任务的边缘结果无法再被采用，就应允许它沿相同安全流程提前停止。这种情形用于检验回退通知是否真的增加了可用信息。

### （二）并发判定实验与强基线

- **B0，固定档位的纯本地执行。** 记录真实本地时延和质量，建立无需边缘承诺时的业务参照。终端使用相同硬件档位，能够处理的任务并发和排队按实际测量记账。
- **B1，补强的因果单边基线。** 利用幂等任务 ID、忙后重新准入、按固定 RTO 查询任务状态并重查持久化结果、有限租约、唯一代际、执行点期限守卫、因果幂等取消与固定回退。准入不足时，在剩余时间允许且无有效执行许可的条件下重试。终端收到相同任务的持久结果时按统一采用条件处理。回退后的取消只能使用当时已知事实，可重发并以任务 ID、代际和状态条件约束。对于确实死亡的本地受管进程，允许按已确认状态回收。存活执行者须完成安全停止或受相应代际与副作用守卫约束，旧执行结束占用且资源管理器允许复用时，才记录物理槽位释放。后继任务实际开始时间另行记账。
- **B2-info，瞬时回退信息参照。** 边缘在终端实际启动回退时立即获知该事实。预知回退检查时刻只说明终端将在该点检查合格结果，实际启动仍取决于检查结果。复用 B1 的取消程序、存储校验、运行中任务停止代价和安全条件。与 B1 的配对差用于估计回退信息迟滞的影响。
- **B2-ideal，瞬时安全释槽参照。** 在相同回退信息的基础上，把确可安全取消的任务从收到取消到可复用的延迟理想化为零。对已产生不可撤销业务效果的任务，照常记录已发生的效果。此条件给出乐观比较点，须验证调度及业务条件后才可就相应指标讨论上界。与 B2-info 的差用于判断停止与归还资源成本的作用。

四路使用相同任务、原始输入、释放时间、质量判据和故障计划。涉及边缘执行的对照保持排队与调度规则一致，并按相同规则处理同一时刻就绪的任务。B1 与后续候选机制共享观测范围、基础执行能力及 SLA。两种 B2 只用于定位差距，分别保留额外信息和即时安全释放这两项理想化条件。B2 的结果不能用来作为实际方案运行时的决策输入。首先用应用层抑制精准复现提交请求、回复或取消受阻，再在 Linux 实际端点用 tc netem 按方向注入延迟、突发丢包及必要的速率变化。各方法复用以场景时间为基准的故障时间窗，分别记录注入参数、端点观测及 TCP 重传可能造成的附加影响。5G-LENA 的 T1 前传容量事件仅作为分段容量扰动的敏感性输入。回放时明确仿真相对时钟、容量单位和服务端链路映射，分别报告该对照。原始表记录仿真时钟及相对应用时间，单位为纳秒，容量为 Mbps。RDINP 往返时延使用端点实际观测。[18][E6]

### （三）指标、分析与判定

主指标为合格结果按期采用率。设一条运行轨迹释放 $N$ 个任务，$Y_j=1$ 表示终端在规定的业务期限内采用了通过核验且达到最低质量档位的结果，否则 $Y_j=0$。单次运行的按期采用率为 $N^{-1}\sum_{j=1}^{N}Y_j$。判定规则同时适用于边缘结果与本地回退。分母保留拒绝、缺失、过期及质量不足的任务，另列边缘采用、合格回退和未达标回退计数。资源方面，记录终端回退后仍被旧任务实际占用的时间，并区分其中可安全释放和不可立即释放的部分。协议开销按请求、回复、重查和取消的次数及字节数报告。安全评价分别记录重复计算、重复业务效果、旧代写入、迟到生效和无法解释的状态跳转。

对声称由无效占用导致超期的个案，须用同一任务 ID 核对持久提交、准入、执行守卫、结果读回、回退或采用和实际释槽。需要查明哪些后继任务当时已就绪、是否因旧任务占用而无法启动，以及在对照路径中是否确实获得了新的执行机会并按期采用合格结果。由此把资源占用变化与具体的业务结果对应起来。

在每个共享任务释放与故障轨迹上，计算 B2-info 相对 B1、B2-ideal 相对 B2-info 的合格按期采用率差，单位为百分点。按预设负载和扰动条件分别报告，同时列出受影响的任务数与资源占用变化。能够取得足量独立轨迹时，按轨迹或故障批次整体配对重抽样，保留同批任务之间的相关性。只有少量轨迹时，报告原始计数及事件见证，待增加独立证据再判断稳定性。具有业务意义的差距以预先明确的 SLA 和资源约束为依据。

若 B1 已满足目标业务要求，或 B2-info 缺少可复现的业务改善，则保留强基线结果并收窄研究。若差距仅在 B2-ideal 中出现，继续核对安全停止与资源回收成本。若瞬时回退信息对照留下可复现差距，则先核查现有取消和公开回退时刻能否消除该差距。只有在这些简单做法仍有不足、且额外交换能改变实际执行决策时，才评价新增协商机制。

### （四）可行性与前期排除路径

已有 SQLite 账本、CPU 执行器和 HTTP 代理验证了部分任务与执行状态可被观测。并发相同输入下的重新准入、运行中停止、物理槽位回收及跨主机时间界需要补齐。首轮将应用层故障夹具、实际执行与网络注入分开验证，使一次异常能够归因到协议消息、执行控制或业务采用的具体阶段。[E1–E3][E7]

在以全 LiDAR BlindMap TMC 分支 epoch 37 进行的 OPV2V 开发回放中，需求反馈组与无反馈补包组的 C−B 为 −0.02125 AP@0.7，策略同时改变了控制开销、等待时间和补包内容，现有试验无法识别需求信息的单独作用。XR 在已完成的 T1 OptimizeRBs 运行中守住了受保护 VR 和云游戏流的 10 ms 期限，尚缺双边机制必要性的证据。两条预研路径为本课题明确了强对照先行的原则，实证重点据此收敛到 RDINP 的限时履约与共享算力可复用性。[E4–E5]

## 四、创新点

**端边承诺与实际履约的衔接。** 研究拟明确资源承诺何时转化为有效许可，许可和期限如何约束执行点，以及结果采用和槽位回收分别需要哪些证据。计划用格式有效但资源不足、承诺有效但执行已经超期、结果可读但未获采用等情形检查这几类约束。现有 C2 状态机、签名、持久账本及代理守卫作为实现基础。拟验证的贡献是将这些约束组合成能追溯到业务结果的时限与资源规则。

**并发履约损失的归因。** 在已有去重、状态重查、租约及执行点守卫的条件下，拟区分终端回退事实到达得晚和旧执行结束得晚对后继任务的影响。两种参照只改变各自针对的条件，并以实际占槽和后继任务的合格交付检验作用。该设计用于回答在哪些任务及链路条件下，改变信息交换时机值得实施。

**有证据支撑的限时恢复规则。** 若强基线下的损失可归因于回退信息迟滞，拟研究如何在有效时限内从终端获取可核验的任务状态，并据此改变边缘执行或回收判断。候选规则需使用同一业务要求和资源预算，观测额外交互的字节与时间，同时通过旧代、迟到和重复生效对照。贡献是否成立取决于这些验证结果。若未得到支持，则按实际轨迹给出适用条件与失败边界。

## 五、研究基础和工作条件

### （一）已完成原型及可复核结果

**C2 协议原型。** 原型具备版本化 JSON Schema、签名输入定义、状态迁移和 SQLite 权威账本，可作为协议与执行接口的起点。已完成 5/5 项定向回归。在另行复核的两项封存受控记录中，分别抑制提交请求和提交回执，终端都观察到 UNKNOWN 并进入恢复所需状态。权威端在请求抑制案保持 RESERVED，提交次数为 0。在回执抑制案到达 CONFIRMED，提交次数为 1。两案受控条件下的终端超时观测相同，业务结果采用仍需另有证据。现有条件证明在方向性有界丢失、处理时间和最后持久化尾段的明确假设下讨论确定性。续跑前应核对实际工作负载能否提供相应条件。[E1][E7]

**DEV02 顺序任务执行。** 已用真实 CPU worker、持久结果与本地回退运行顺序任务。在 800 ms 的开发任务期限内，48/48 次任务均在终端发布截止前交付，输出摘要全部匹配，其中含低分辨率回退。真实业务的最低质量档位及最终采用条件仍需按该业务的 SLA 确认。在使用相同输入的首轮与重复轮顺序任务中，C2 路径的 12 个次任务均因逻辑配额被拒，直接持久租约路径的 12 个次任务均完成边缘处理。这证明现有对照能够揭示逻辑配额与物理执行占用的差异。配额释放、结果重查和多任务并发下的后续需求将在新对照中分别观察。[E2]

**DEV04 真实代理执行。** 已在 Caddy v2.11.9 上验证配置变更和 HTTP 业务读回。在受控扣留个案中，仅启用发起方守卫时，该守卫已通过，而新业务读回仍比截止晚约 85.45 ms。加入执行点守卫的对照拦截了该迟到变更。另一受控运行中，管理确认和首次新路由业务读回均已发生时，一个被扣留的旧请求仍在途，随后才返回。这为分别记录管理确认、实际生效和旧请求排空提供了执行面见证。当前排空证据对应该在途请求，整体排空上界仍需额外验证。[E3]

### （二）设备、环境及待补工作

本机具备 Windows、Python、SQLite 和 Caddy 的已有运行条件，可继续复测同机协议、账本、CPU worker 与 HTTP 路由。远端 Ubuntu 已完成 SSH 可达性核对，并能提供 Linux 进程和网络注入环境的候选条件。首轮 CPU 载荷不依赖 GPU。跨主机正式端点、双向故障注入权限、时钟映射误差与故障回放结果须在部署预检中核验，随后才用于实验结论。

拟沿用原型的持久提交标记、执行进程事件和 HTTP 读回，补齐业务采用或回退决定、取消生效、运行中停止和实际可复用的时间记录。原有释放时间字段采集于账本事务内，新的并发对照将核对释放记录是否已提交，并用后续准入与执行日志核验容量确实归还。旧日志记录应保留在原目录，新运行记录固定代码版本、输入清单、故障窗口、系统配置、原始事件和计数规则。已有协议和设备可支撑原型阶段，业务 SLA、并发负载和可安全取消条件是首轮需要单独确认的实验前提。[E7–E8]

## 六、研究计划

| 阶段 | 主要工作与阶段交付 | 判断与处理 |
| --- | --- | --- |
| 开题及业务确定 | 核对学院要求、目标 SLA、回退质量和旧请求排空语义。确定软件、数据与标准版本。交付开题报告与协议字段清单。 | 如果尚无可核对的业务 SLA，先固定明确标注的开发夹具及质量判定规则。 |
| 基线工程与预检 | 以首两周完成并发首轮为计划目标。实现 B0、补强 B1 和两类 B2，补齐任务贯通日志。在同机核验少量任务，再验证跨机端点和注入配置。交付复现实验清单与事件字典，完成至少一条从授权、执行到终端采用或回退的可复核事件链。 | 时间戳不可信、执行槽审计不完整或发生未解释的旧代写入时，先修正实验基础，再开展成组比较。 |
| 配对判定与机制取舍 | 预先固定 SLA、负载档、故障窗口、配对单位和分析规则。核对 B1 与两类 B2 差距，沉淀失败见证、开销和资源归因。 | B1 已满足业务目标且 B2-info 缺少可复现改善时，停止追加协商轮次。仅 B2-ideal 有改善时，收窄至停止与回收边界。 |
| 有依据的机制评估与小论文 | 根据残差构造最小方案，复测及时、迟到、重复、回退及重启，并在未用于机制选择的负载或故障计划上比较。交付源码、复现材料及论文稿。 | 改善不能复现，或引入违背最低质量、过期效果或不安全复用时，如实保留结果并调整论文论断。 |
| 硕士论文整合 | 完成从资源意图规格、限时性质到履约实证的完整论证。结合实际资源接口与时间评估条件选择扩展。归档数据和软件版本。 | 动态发现及频谱执行依赖独立的接口权限和实验条件，优先保证首轮算力闭环可复查。 |

各阶段以能够重跑的最小脚本、事件证据和结论记录为验收标准。保留被拒与回退任务、运行异常及空结果，写明未覆盖的业务和链路条件。开题后可根据导师确认的 SLA 与学位进度更新实验里程碑。在正式采集比较数据前，应固定判断准则。已有预研结果和探索性测量用于工程准备，独立评价以事前确定的测量规则与新轨迹为准。
