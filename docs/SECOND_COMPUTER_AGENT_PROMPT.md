# 发给第二台电脑 Codex 的提示词

请整理这台电脑上与论文 1 相关的研究分支，将可协作的资产上传到现有私有仓库 `sh12520/paper1-research`。交付一个可供主电脑审查的 Git 分支，并实际测试仓库的导航能否让新 Agent 快速理解该方向、核对证据并找到历史经验。

## 1. 接入同一个私有仓库

- 先确认本机当前工作目录、Git 工作区状态和目标远端。用这台电脑已配置且有仓库权限的 GitHub SSH 身份访问 `git@github.com:sh12520/paper1-research.git`。各电脑使用自己的身份，密钥材料留在对应设备。
- 已有这个仓库的本地副本时先 `git fetch origin`。工作区干净时，从最新 `origin/main` 创建 `research/<方向短名>` 分支。方向短名使用简洁的英文小写和连字符。工作区有未提交改动时，用单独工作树或独立检出完成整理，保留现有改动。
- 如果尚无副本，可以先用 `git clone --filter=blob:none --sparse git@github.com:sh12520/paper1-research.git`，进入克隆目录后执行 `git sparse-checkout set docs literature research rdinp csods`。需要原档案时按全局目录补取目标路径。只用这个仓库，并将本机研究源目录作为取材来源。

## 2. 先定位，再整理

- 从仓库根目录的 `AGENTS.md` 开始，按需阅读当前推进、关键证据和全局目录。先用目录名、研究关键词、任务或实例 ID 搜索。找到相关项目时，只打开决定当前判断所需的报告、表或少量记录。
- 只读盘点本机研究方向的原始目录、阶段、状态、代码、报告、文献和实验结果。与仓库已有材料按实际路径、版本或文件摘要比对。已有内容用链接复用，补齐真正新增的部分。
- 保留本机原始文件及历史 Git 工作区。新导出的资产放入 `research/<方向短名>/`。用简短、可移植的相对链接组织入口，按实际内容使用如下结构：

| 路径 | 内容 |
| --- | --- |
| `README.md` | 研究问题、适用场景、与现有路线的关系、最小入口 |
| `CURRENT.md` | 当前状态和日期、已通过与未通过事项、下一项决定性验证 |
| `EVIDENCE.md` | 关键结论 → 报告 → 汇总表或指定实例，记录样本、环境和验证边界 |
| `REFERENCES.md` | 本方向关键文献、稳定标识与对应研究问题。已有的仓库文献条目直接链接 |
| `src/`、`reports/`、`results/` | 按需放入可运行源码、代表性报告和必要的研究结果 |

- 把现场实证、受控工程测试、开发回放、待证假设分清楚。保留负结果和失败原因。既有结果有足够证据时优先只读复核。实验未执行、原始材料缺失或权限不足时，直接在索引记明。
- 入库范围限于用户有权共享的研究资产。密钥、令牌、会话记录、授权文件、未启用的持出数据、第三方大原始数据、依赖二进制和缓存留在本机。需要追溯外部数据时，记录数据来源、版本、可用的摘要及获取条件。

## 3. 以新 Agent 身份复核全局导航

从 `AGENTS.md` 出发，实际完成以下三项查找，并在 `research/<方向短名>/NAVIGATION_REVIEW.md` 记录打开的文件、是否成功以及具体断点：

1. 找到当前在推进的研究、已知边界和下一项决定性验证。
2. 选一条已有结论，沿报告、结果表和一个实例或记录核对出处。说明结论属于哪类证据。
3. 找到与新分支相关的一项历史失败或已验证经验，判断本方向会复用什么，哪里可能重复已有工作。若提到潜在机会，写清需要什么证据以及什么结果会使之停止。

也从 `literature/README.md` 实际定位一条与分支相关的题名、DOI 或 arXiv ID。已有书目可直接复用。若本机没有 Zotero 或 Undermind，先用 `literature/references.bib` 和正式来源核对，记录哪些入口与权限需要补齐。

同时检查新增方向从全局目录应如何发现，列出建议新增的仓库相对链接。将跨方向导航调整建议留在审查记录中，主电脑合并时统一处理。

## 4. 自检并交付

- 检查新增链接能打开，关键数字能定位到证据。运行与整理内容相关的已有小型检查，记录命令和结果。避免调起旧确认流程或重复大规模运行。
- 只暂存本次预期目录，再逐项审查文件路径、大小和内容。运行 `git diff --cached --check`，并检查正文与文件名中是否含密钥、私有路径、授权材料或误纳入的可重建产物。
- 在 `research/<方向短名>` 分支提交，用 `git push -u origin research/<方向短名>` 上传。通过 `git ls-remote --heads origin refs/heads/research/<方向短名>` 核对远端提交与本机一致。保留该分支供主电脑审核合并，默认分支继续维持原状。
- 最终回复给我：研究方向、远端分支、完整 commit SHA、入口 `README.md` 的仓库相对路径、已验证的证据和仍缺的材料、导航审查结果、以及保留本地的资产类型。SSH 无权限时说明具体失败，继续完成本地整理。
