## 请比较的方向

1. **暂定首选，RDINP 限时服务履约。** 本地受控试验中，终端同样看到 `UNKNOWN` 时，权威端可能未提交或已提交。Caddy 试验还分离了管理确认、首次新路由读回和旧请求结束。实际终端何时采用结果需另行核对。请把问题收窄到一种具体终端–边缘任务。启用幂等、状态查询、有限租约、唯一代际、执行点期限守卫和既有本地回退后，是否仍可能发生有价值且可测量的按期交付损失？请指出可查的 SLA 来源，及如何获得同一任务 ID 上的授权、提交、执行、业务读回和回退轨迹。如果建议双边协商，请明确双方各自掌握什么信息、能采取什么动作，以及为何强单边对照无法替代。
2. **暂定备选，OPV2V 时限感知与工程复用。** 测试过的反馈策略 C 弱于普通补包 B，请求开销、等待和补包内容同时变化。预筛、接收流水线和去重有开发证据。请区分真实 CUDA 服务计时、模型链路回放和未执行的跨任务对照。现有 35、45、50 ms 为开发阈值，真实 SLA 待核。请判断该线索能独立成题、只能作为单边强对照，还是在取得真实业务轨迹后可成为 RDINP 的应用。请说明什么新证据才会改变你的判断。
3. **CS-ODS 历史比较。** 有方法、证明和开发比较，独立确认未运行。请在能实质影响选题时再讨论重启它，并指出与最接近的强通用基线及当前场景的关系。各方向可以并行保留，避免为凑题把候选生成、感知调度、执行履约当成同一个问题。
