## 当前证据与边界

G1-A 用单台 Ubuntu 上的真实 CPU 图像工作负载，完成 144 个配对、432 次实测方法运行及 5,184 条任务×方法记录。故障为分向应用消息抑制，质量与截止期来自开发夹具。实测包括纯本地 B0、增强单边 B1、瞬时回退信息 B2-info。B2-info 与 B1 共用安全停止和实际释槽路径。B2-ideal 在 B2-info 的实测授权轨迹上作独立模型回放，只将停止至槽位可复用的时长置零。

在事前指定的 96 个中高负载配对中，B2-info 减 B1 的合格按期采用率差为 −0.174 个百分点，95% CI 为 [−0.434, 0.000]。两组均未观测到槽位不足导致的准入拒绝。B1 在回退前获得有效授权的任务为 150/1,728，低档回退路径中有 874 项在截止前触发回退、截止后才启动计算。可定位阶段，延迟归因仍需分离。当前判定为 `INCONCLUSIVE_REQUIRES_MANUAL_REVIEW`，等待作者决定后续行动。

请同时核对公开回退点的条件论证。当前夹具采用共同时间基准，终端只在公开回退点前采用已持久化的边缘结果，结果提交同时释放槽位，终态任务不能再次取得该槽。对回退点仍持槽且可安全停止的纯计算任务，边缘可依据现有信息进入同一停止路径。请判断这些条件在具体业务中会怎样失效，以及新增交互能否改变实际执行。

## 请给出的判断

1. **选一个首要方向。** 判断最值得做的是补测真实共享槽位争用，转向具体的履约失败（如旧执行者副作用、在途请求与新任务时限冲突或不可预知的多档回退），还是先取得可信业务与 SLA。说明你的理由、可证伪问题和最可能改变判断的反证。若建议补测，请区分“在原夹具中通知是否包含新信息”和“出现实际争用后是否发生可归因的后继损失”。解释已有结果时沿用冻结判定范围。
2. **给一项两周内可完成的最小验证。** 写明业务主体、SLA 或依据、可执行动作、最强因果单边基线、同输入配对与指标分母。列出需要记录的有效授权、任务就绪与占槽、结果采用、回退、安全释放及后继任务事件。说明如何分离同机调度和真实容量竞争，明确继续、转向或停止的条件。若建议双边协商，请指出彼此独有的信息或动作、时效、它能改变的执行决定和消息成本。
3. **审查开题及两阶段 Goal。** 指出正文中应保留的证据、应收窄或改写为待验证的主张，以及小论文验收能否支撑硕士论文扩展。请给对应章节和一两句具体改写。评价频谱条款先在协议与 Schema 中表达、首轮闭环用边缘算力槽位、动态发现可选的范围是否合适。请给两三条最贴近的原始论文或正式规范，注明相关章节、实际验证范围和与本课题的差别。
